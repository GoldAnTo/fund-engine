# Research Operating System 基线蓝图

> **状态：已确认的产品与改造基线，尚未代表功能已实现。**
>
> 本文记录 2026-08-08 已确认的讨论、边界、原型和改造目标。后续可以调整，但必须以本文为起点：新增或修改决策应追加到文末“变更记录”，不得悄然覆盖本文件中的已确认边界。

## 1. 产品要解决的问题

Fund Engine 不是全市场金融终端、泛 AI 搜索或一次性研报生成器。它为专业行业研究员提供持续研究的工作系统：将事件、新闻、研报、上传文件和粘贴资料转化为可复核的研究判断，并继续验证判断对公司、股票和基金披露暴露的有条件影响。

最终交付不是“AI 说某个主题会涨”，而是：

```text
资料 / 事件
  → 研究问题与竞争命题
  → 原子陈述与证据审核
  → 研报主张与关键因素
  → 后续数据验证
  → 公司基本面与股票市场观测
  → 基金历史披露暴露
  → 持续监控、复核与版本回放
```

首个商业切入宜选择少数高信息密度行业，例如海外 AI / 半导体事件如何穿透至中国公司与基金。目标客户是需要审核、留痕、复盘和持续跟踪的中国机构行业研究团队，而不是需要覆盖全市场的终端用户。

## 2. 不可改变的产品边界

1. 研究材料、人工审核与正式判断优先于摘要、聊天或漂亮图谱。
2. AI 只能提出主张、实体、关系、关键因素或资料候选；所有 AI 输出都必须可见地标为“未经人工复核”。
3. 正式验证结论只能为 `supported`、`contradicted`、`insufficient_evidence`、`not_due`，并可回到原文、时点、范围与审核记录。
4. 研报中的事实、预测和研究意见必须分别表示，不能把研报观点当作已确认事实。
5. 价格走势、基金收益或两条关系共现不能自动构成因果传导；证据不足时必须明确写“证据不足”。
6. 基金只能按历史披露持仓表达，必须显示报告期、披露日、采集日、来源、覆盖率和过期状态；绝不伪装为实时仓位。
7. 不产生自动买卖、持仓、目标价、收益或交易指令。
8. 不做全市场信息流、全量数据终端或无来源/无许可约束的聊天问答。

## 3. 用户、首页和信息架构

### 3.1 主用户

行业研究员每天处理新材料、审核 AI 提议、维护行业命题、识别反证、追踪下一验证事件，并将已验证的研究关系谨慎地映射到公司、股票和基金披露。

### 3.2 首页：研究调度，而非单个 Case

首页是“研究调度”，要在五秒内回答：**今天先推进哪一个判断？为什么？其他研究正在做什么？**

- 多个 `ResearchCase` 是独立研究单元，首页按决策影响而不是主题热度排序。
- 优先级顺序：阻塞正式结论的关键证据 → 可能推翻已发布结论的新材料 → 需要确认研究范围 → 一般新材料。
- 首页提供“从事件开始”和“导入/粘贴资料”入口；资料先进入收件箱，用户决定归入既有 Case 或创建新 Case。
- “待我处理”是跨 Case 的二级入口，不替代首页调度。

### 3.3 单个 Case 工作台

Case 工作台是具体研究详情，不是首页。标题区提供 Case 切换器与“返回研究调度”。切换 Case 不得带入其他 Case 的结论、审核状态、版本、资料归属或未审核提议。

Case 稳定导航：

1. 结论；
2. 命题与证据；
3. 原文资料；
4. 审核；
5. Wiki 图谱；
6. 市场与表达；
7. 监控与版本；
8. 关联研究。

Case 首屏始终优先展示当前判断、关键反证、最大缺口、竞争命题和唯一下一操作。右侧“证据与行动”栏必须解释：为什么需要该动作、用户要做什么、完成会解锁什么。

### 3.4 已确认视觉方向

视觉方向为“静谧证据案头”：暖灰纸面、深石墨文字、低饱和苔绿色表示已审核/可执行、砖红仅用于反证/风险/阻塞、蓝色仅用于链接和焦点。它应像长时间使用的研究案头，而不是金融终端、SaaS 卡片墙、聊天界面或知识图谱演示。

## 4. 多入口资料与来源治理

### 4.1 入口不锁死

以下都可创建或补充一个 Case：

- 事件与新闻；
- 聚源等已授权供应商的研报、公告、新闻、行情、基本面或基金数据；
- 其他外部研报；
- 用户粘贴内容；
- 用户上传文件。

聚源是高质量、授权清晰的供应商适配器，不是唯一入口。不同来源的“可浏览、可检索、可供 AI 处理、可导出、可通过 API 使用、可作为正式证据”的权限必须独立控制。

### 4.2 所需的来源对象

现有 `DocumentVersion` 只记录 hash、URL 和片段，后续需补足下列模型或等价能力：

| 对象 | 必须记录 | 目的 |
|---|---|---|
| `SourceContract` | 供应商/租户、允许展示/检索/AI/导出/API、地域、有效期、保留/删除与下游限制 | 将许可变成可执行规则 |
| `ProviderRecord` | 供应商记录 ID、请求口径、原始响应或可重取凭证、hash、获取时间、合同版本 | 复现供应商资料 |
| 上传资料记录 | blob/对象版本、MIME、上传人、租户归属、保留策略 | 支持上传文件且不丢原件能力 |
| 粘贴资料记录 | 粘贴原文、粘贴人、可选原始 URL、核验状态 | 将粘贴作为线索，不伪装为已核验来源 |
| 来源准入类型 | `licensed_provider`、`uploaded_file`、`pasted_snapshot`、`public_url` | 不将内部来源伪装成 HTTP URL |

来源缺少必要许可或核验时可以保留为线索，但不得越权处理、导出或采纳为正式结论证据。

## 5. 研究、审核和持续运行

### 5.1 审核关键证据

当待审证据会阻塞结论时，主操作为“审核 N 条关键证据”。审核页使用左右分栏：左侧冻结原文和精确 locator，右侧 AI 提议、支持/反驳角色、适用范围和历史审核。用户只能确认、驳回或要求补充，并必须填写理由；不提供高风险批量通过。

### 5.2 资料阅读

原文阅读必须展示来源类型、提供方、发布日期、获取时间、内容版本、许可范围、解析状态和精确位置。若只有内容快照，则只能称“内容快照”，不能称原件 PDF。用户从资料段落创建的关系只能成为待审核提议。

### 5.3 新材料与结论复核

新资料若可能改变已发布结论，用户进入“变化比较”：并列旧结论/原有依据与新资料的精确变化。用户必须选择“纳入重新复核”或“记录为不改变当前判断”，并填写理由。前者创建新版本，旧结论永远可回放。

### 5.4 CaseMonitor 与 OpenClaw

每个 Case 可设置 `CaseMonitor`：关注命题/公司/关键词、允许资料源、频率、下一验证事件、预算上限与暂停状态。没有明确范围和下一验证事件的 Case 不启用定时补证。

OpenClaw 或等价调度层只做：领取到期 `CaseMonitor`、重试、失败通知与调用受控运行接口。它不直接写正式结论、基金暴露、交易指令或绕过来源许可。研究规则、原始资料、证据审核、版本和影响判断始终归 Fund Engine 所有。

“立即补证一次”与定时任务创建同一条受控 `ResearchRun`。运行对用户必须可见：触发原因、检查范围、允许来源、阶段、材料数、支持/反证/范围不一致候选数、失败原因、预算与下一步。运行完成只会产生：

1. 无关键变化，记录检查而不改变结论；
2. 关键待审材料，主操作变为审核证据；
3. 可能影响已发布结论，主操作变为决定是否重新复核。

### 5.5 全局运行透明度

运行透明度是全局交互规则，而不是“监控与版本”页的附属信息。只要存在活动中的
`ResearchRun`，任何 Case 页面和研究调度页都必须显示一个紧凑、可展开的运行状态条：
Case 名称、当前阶段、确认过的研究范围、允许资料源、已处理数量与下一次可能的人工动作。

展开面板必须按时间顺序显示本次运行的可复现事实：触发人或定时原因、CaseMonitor
配置版本、查询/筛选口径、每一阶段的开始与结束、冻结材料、因权限或范围被排除的材料、
候选输出、失败原因和下一步。面板不得泄露无权资料正文，也不得把运行中的候选写成正式
结论、市场影响或基金暴露。

用户可以暂停未来定时任务、发起一次立即补证，并修改频率、确认过的因素范围、允许来源、
预算上限和下一验证事件。修改必须追加新的 `CaseMonitor` 配置版本；历史运行永远引用其
开始时的配置版本，以便回放与审计。

## 6. Case 关联与本地 Wiki 图谱

### 6.1 Case 关联

`CaseRelation` 可用类型：`shared_driver`（共享驱动）、`follow_up_validation`（后续验证）、`potential_conflict`（可能冲突）、`shared_material`（共享资料）。每一条必须有理由、创建人、时间和审核状态；AI 只能提议。

关联用于发现相关工作，不能继承结论、审核结果或证据。共享资料被目标 Case 使用前，仍须重新确认来源权限、范围、证据角色和人工审核。

### 6.2 Case Wiki 图谱

本地图谱是从不可变证据账本构建的可重建读模型，不是事实来源。默认进入单 Case Wiki，完整跨 Case 研究网络只是第二层下钻页。

核心路径：

```text
DocumentVersion → SourceSpan → SourceStatement → EvidenceLink
    → Thesis / KeyFactor / Company / Stock / HoldingDisclosure / Fund
```

图谱默认分两层：

- 已审核节点/关系：实线，可参与正式判断；
- AI 候选：虚线，明确标“未经人工复核”，只能进入审核队列。

点击任何节点或边，右侧检查器必须显示原文、精确定位、来源许可、可得时间、关系类型、范围、审核人和理由。图谱不应替代 Case 首屏或证据阅读。

## 7. 研报主张、关键因素、股票与基金表达

### 7.0 研报抽取质量主链路

研报解析不是一次“摘要”或一次模型调用，而是将**版面解析、陈述候选、机器校验、金标回归和人工审核**分开的质量门槛。任何一步失败都只能保留候选或线索，不能写入正式证据账本、驱动股票/基金表达或改变正式结论。

已确认的主链路如下：

```text
Docling + PP-Structure
  → 页码 / 段落 / 表格 / 单元格 / 阅读顺序
  → LLM 或 PP-UIE 生成 AtomicClaimCandidate
  → quote 必须是原文连续片段，校验 offset + hash
  → 数值 / 单位 / 期间 / 主体 / 来源权威性校验
  → FinQA / TabFact 式金标回归
  → SciFact 式支持、反驳、证据不足核验
  → 人工审核通过
  → 才写入正式 SourceStatement
```

`Docling` 是版面和可定位结构的优先解析底座；`PP-Structure` 用于中文 OCR、扫描页及复杂表格的交叉解析。两者都不判断金融事实。关键 KPI 表格可以由确定性表格解析器进行二次核验；表格解析质量分不能代替数值口径判断。

`AtomicClaimCandidate` 是不可直接采纳的候选，最少包含：逐字 `quote`、原文 offset/页码/坐标、文档与 quote hash、主体、谓词、对象或数值、单位、期间、适用范围、断言者、主张类型、候选生成版本和全部机器校验结果。一次陈述只表达一个可独立判断的主张；不能把事实、预测、归因和研究意见合并在同一候选中。

陈述类型至少拆为“主张性质”和“断言者/权威性”两个维度。券商研报对公司公告或数据的转述初始只能是二手转述，不能仅因文本写着“披露显示”而成为 `disclosed_fact`；只有找到并冻结相应公司公告、财报或获准的原始数据后，才可关联并升级为已披露事实。管理层预测仍是预测，研究员判断仍是研究意见。

模型、提示词、解析器或规则升级前，必须在版本化中文研报金标集上回归。金标集保留双人标注、分歧裁决和原文定位；衡量逐字引用/定位命中率、原子陈述 precision/recall、重复率、事实/预测/意见混淆、数值/单位/期间/实体错误以及人工审核通过率。逐字引用与 hash/offset 机器校验必须为 100%；高影响陈述（关键因素、股票/基金表达、正式结论）必须人工审核。

### 7.1 指标词典、机制模板与可研究性门槛

为避免每篇研报由模型临时决定结果变量和关键因素，所有进入正式验证的 `ReportClaim` 必须使用受控、可版本化的 `MetricRegistry`、`MechanismTemplate` 与 `ResearchabilityGate`。完整设计见 [固定结果变量与机制模板设计](../superpowers/specs/2026-08-08-metric-and-mechanism-template-design.md)。

`OutcomeBinding` 固定命题的结果指标、实体/业务范围、方向、基线和时间窗；`MechanismTemplate` 明确 `required_for_outcome`、`required_for_attribution`、`alternative_explanation` 与 `scope_guard` 节点角色；`VerificationRule` 明确支持/反驳条件、允许来源、验证窗口和下一验证事件。模型只提出可回到原文的候选，研究员负责确认绑定、模板版本、必要节点与阈值。

没有已审核结果变量、模板版本、可观测反证/替代解释和完整时点/范围的材料，必须停留在线索或研究计划，不能写入正式证据、结论、股票市场表达或基金披露表达。业务线主结论至少需要两个独立主指标；只有一个主指标时只能作为 `single_metric_monitoring`，结论不得高于 `insufficient_evidence` 或 `not_due`。

首个模板限定为“海外 AI CapEx 到中国硬件公司”：客户实际 CapEx → 相关技术/架构投入 → 目标公司订单/份额 → 交付/出货 → 相关业务收入 → ASP/成本/毛利率 → 利润结果。仅有行业景气、客户 CapEx 或公司总收入增长均不足以自动声称传导成立。

### 7.2 从研报到验证

解析研报后产生 `ReportClaim` 候选，至少包括原文定位、类型（`disclosed_fact`、`forecast`、`research_opinion`）、实体、观察期与提出者。研报主张不是自动确认的事实。

每个需要验证的研报主张对应一个或多个 `KeyFactor`，它至少有：名称、预期方向、适用公司/股票、验证指标、允许数据源、验证窗口、支持/反驳条件、下一验证事件、审核状态和理由。

`ClaimVerification` 只允许 `supported`、`contradicted`、`insufficient_evidence`、`not_due`。持续研究和立即补证围绕关键因素执行，而不是围绕模糊的“找利好/利空”执行。

### 7.3 市场与表达页

该页的影响路径为：

```text
ReportClaim → KeyFactor → ClaimVerification
  → Company / Stock → HoldingDisclosure → Fund
```

它必须把下列三类证据分开显示：

| 层 | 数据与判断 | 约束 |
|---|---|---|
| 基本面影响 | 订单、交付、收入、ASP、毛利率、EPS 修订、估值等 | 需要已审核传导关系 |
| 市场观测 | 可得时间、事件时间、T0/T+5、基准、价格源、盘后处理、相对表现 | 描述发生了什么，不自动证明因果 |
| 基金披露表达 | 命中股票、基金、权重、报告期、披露日、采集日、来源、覆盖率、过期状态 | 仅历史披露，绝非实时仓位 |

“立即补证此因素”只依据该因素的指标、验证窗口和允许数据源创建 `ResearchRun`，不能自动改变正式结论或产生投资指令。

## 8. 原型验收合同

下列交互原型已经讨论并确认。它们是后续 UI 实现的验收合同，而非已经合入产品的前端代码：

| 原型 | 用户任务 | 必须保留的交互 |
|---|---|---|
| 研究调度与 Case 网络 | 从多个研究中决定今天先做什么，并进入一个独立 Case | 优先处理队列、独立 Case 切换、关联不继承结论 |
| Case 持续研究 | 理解系统正在做什么，并手动立即补证 | `CaseMonitor`、立即补证、运行阶段/结果/失败明细、唯一下一操作 |
| Case Wiki 图谱 | 从资料到命题、实体和关联 Case 检查关系 | 审核/AI 候选图层、点击检查器、精确原文与许可、审核入口 |
| 市场与表达 | 验证研报主张并下钻股票/基金披露 | 关键因素、基本面/市场观测/基金披露分层、事件窗口与持仓时点边界 |

开发前应将这些原型从运行时 `.superpowers/` 目录重新实现为受测试的前端页面，而不是直接把原型 HTML 当生产代码。

## 10. 分阶段改造目标

### 阶段 0：保护现有工作

- 让当前事件研究与影响功能完成、测试和提交；
- 不以新产品规划重写其生命周期或污染未提交工作；
- 记录可复用 API、模型和前端路由。

### 阶段 1：资料准入与多入口

- 建立 `SourceContract`、`ProviderRecord`、上传/粘贴元数据和来源类型；
- 增加资料收件箱、归入已有 Case/创建新 Case；
- 覆盖许可、AI 处理、导出、保留和删除的拒绝路径测试。

### 阶段 2：研究调度与持续研究

- 建立研究调度首页和 Case 切换；
- 建立 `CaseMonitor`，支持立即补证、定时任务、运行明细、重试和失败可见；
- 将 OpenClaw 以外部受控调度器适配，不作为领域事实写入者。

### 阶段 3：Wiki 图谱与 Case 关系

- 新增 `CaseRelation`、`ReportClaim`、`KeyFactor`、`ClaimVerification` 的不可变版本与审核流；
- 从证据账本重建 Case Wiki 图谱，分离已审核与 AI 候选图层；
- 再建立全局研究网络，只用于发现关联和下钻。

### 阶段 4：股票、基金与市场表达

- 为每个关键因素接入真实、具授权和带时点的数据源；
- 建立基本面、市场观测、基金披露三层读模型与界面；
- 实施事件窗口、基准、价格源、可得时间、报告期/披露日/采集日和覆盖率门禁；
- 以一条窄行业链路的真实 Case 验收，而不是扩张全市场数据量。

## 11. 验收门槛

1. 研究员在研究调度首页和单 Case 页面都能在五秒内说出当前优先工作与原因。
2. 每个正式判断、关键因素和市场表达都能回到获准使用的冻结资料、精确 locator、审核记录和时点。
3. 资料来源、AI/导出权限、租户、保留期和删除策略是可执行数据，不是 UI 文案。
4. 立即运行与定时运行使用同一受控路径，显示运行范围、输出、失败与下一步。
5. 图谱可以从账本重建，候选关系不会被误读为已审核关系。
6. 股票市场观测不能绕过事件窗口、基准和可得时间；基金披露不能绕过报告期、披露日和采集日。
7. 一个真实行业试点应至少有竞争命题、支持项、反证或明确缺口、可验证关键因素、公司/股票表达与基金披露表达。
