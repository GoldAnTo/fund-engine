# FundClaw 原型一致性修复与复核

日期：2026-09-09。针对用户指出“现在做的东西跟原型相差很多”，本轮以已确认的 `docs/prototypes/fundclaw-team-workspace-v2.html` 为界面基准，修正真实工作台的信息架构、布局和操作入口。已更新本机正式服务 http://localhost:5180/ 。这是一轮原型对齐交付，不代表整条真实研究链路已经全面验收。

## 1. 偏差与已实施修正

| 原型要求 | 此前偏差 | 本轮实现 |
|---|---|---|
| 左侧研究与问题、中间角色协作、右侧证据三栏 | 专业角色与原生过程分散，详情占据主画面 | 正式路由接入 `ProfessionalTeamWorkspace`；1440px 下左栏 250px、右栏 365px，中间自适应 |
| 四位角色在同一工作流中可见 | 以单个角色的大段详情为主要阅读方式 | 默认呈现产业、财务、策略、AI 质控四张紧凑卡；摘要、实际状态、缺口、产出、证据入口同卡展示；全文按需展开 |
| 简洁标题与研究范围 | 长请求、运行信息压缩内容区域；范围字段不足 | 标题压缩并支持展开；服务端提供已冻结主题、证据截止和来源政策的安全投影；缺失的主体不从登录身份或可变对象推断 |
| 对话、时间线、产出三个视图 | 专业团队与原生结果缺少稳定容器 | 三个工作区标签、五个角色筛选、工作记录展开；原生研究过程与结果保留在对应视图 |
| 底部固定输入、定向角色消息 | 内容或状态切换会挤走输入，加载完成可能丢草稿 | 稳定的输入插槽；按研究轮次隔离；问题入口选中负责角色并聚焦输入；Enter 发送、Shift+Enter 换行；历史版本禁止发送 |
| 证据与来源 / 待解决问题 / 审查状态 | 证据联动与专业产出分离，复核信息层级不清 | 右栏三个标签常驻；角色证据按实际产出 ID 与已授权证据交集筛选；打开冻结原文并返回触发按钮；显示真实 AI 六项检查与独立人工复核 |
| 明确当前与历史版本 | 历史视图的工具栏仍可能显示最新版本；后续复核误归为历史 | 显示“查看版本 / 最新版本”；复核记录按早于、等于、晚于所选版本分组，后续记录默认折叠；精确旧任务依赖继续可追溯 |
| 空态和窄屏保留工作台结构 | 新建页观感与原型断裂；极短屏工作流几乎无可见高度 | 空态采用同一骨架，四角色明确未绑定；窄屏切换工作区与证据，短屏收起范围并保留展开入口 |

数据来自真实 API 与任务，不复制原型的演示公司、附件、日期、状态或结论。角色产出入口当前打开真实保存的草案；没有伪造 PDF / XLSX 下载。检索方向标签不表示已验证的支持关系。AI 完成不表示人工审核通过。

## 2. 同步修复的可靠性问题

- 提交准备阶段增加同步栅栏，防止哈希尚未完成时重复提交；取消及身份切换覆盖准备阶段。不可写的 sessionStorage 使用明确的内存回退；未知结果保留原请求与幂等键，409 重试不创建新键。
- 证据插槽复用现有私有读取控制器，不新增第二套轮询或绕过失权清除。原文版本绑定、哈希检查和授权边界继续保留。
- 冻结范围 DTO 仅白名单展示字段，不暴露原始材料或完整冻结协议。
- MiniMax 启动解析增加明确的纯 JSON 输出约束，继续严格拒绝 Markdown 围栏和额外文本；没有通过剥离围栏或无限重试掩盖失败。一次有界的真实 MiniMax 启动解析成功，详见 `2026-09-09-minimax-startup-json.md`。
