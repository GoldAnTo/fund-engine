### 3.1 前端布局与操作逻辑建议

现有三列布局适合桌面研究，但字体/控制密度较高，证据层仍以多张相似卡片堆叠。下一步应围绕任务完成设计，而不是增加装饰：

1. **真实研究入口**：新建表单只收必要的资料、研究问题和时间范围；提交后以服务端 Case ID 跳转，明确 queued/running/waiting/failed 状态，刷新可恢复。失败保留输入，不能回退到 mock。
2. **继续工作优先**：研究列表支持状态/时间过滤；首页优先显示阻塞、待审核和最近变化。移动端增加页面内快速跳到证据/输入的导航，减少长滚动。
3. **证据可追溯**：展示真实 source/version/span ID、日期、原文定位和审核状态；来源链接打开冻结原文。相关性、支持关系和人工核验是不同属性，不能用绿色勾号代替审核事实。
4. **任务与消息区别**：人类本地文本、已提交命令、后端任务事件和模型输出使用明确标签。服务端确认后才显示已提交；网络中断与重试不重复创建任务。
5. **列表性能**：真实数据接入后使用分页/增量载入、可取消请求与过期响应保护；数量增长后再验证虚拟列表，不为当前 5 条示例过度优化。
6. **无障碍**：下一轮覆盖 200% 缩放、屏幕阅读器、对比度和触控目标。当前正文/辅助标签约 10–13px，建议结合信息层级提升小字可读性；本轮不宣称全面 WCAG 2.2 AA。
7. **设计规范**：提取现有 token/组件规则形成 DESIGN.md。保持现有克制绿色和熟悉控件，不做无依据的全站视觉重建；生产集成完成后移除长期无用途的禁用演示入口。

### 3.2 后端运行与权限建议

- 为每个路由定义资源范围：tenant-owned Case、从属 thesis/document/review/job，或共享目录。后端统一实现“解析资源 → 所属 Case → tenant 校验”，不能仅依赖前端隐藏入口或不可猜 UUID。
- 对每个受保护资源建立 owner/foreign/anonymous 三组测试，覆盖读取、列表过滤、写入、取消/重试和对象关联。不可通过 payload.created_by 自报身份建立所有权。
- 旧无来源创建已退役：匿名 401，认证后 409、零写入，指引已有事件研究创建入口。公共流程回归覆盖事件创建后 workbench 200、添加 thesis 201，无手工 admission 掩盖。
- 在隔离 PostgreSQL 上测试两个 worker 竞争领取、lease 过期、取消与完成交错、事务回滚/重试、幂等键冲突；SQLite 通过不代表锁语义一致。
- 增加 readiness（数据库连通和迁移版本），保留 /health 作为 liveness；worker 监控区分“活着”和“在推进”，展示队列等待时间、最后成功/失败及重试次数。
- 上传在代理、multipart、解码层分别设资源边界，验证慢上传、损坏/压缩 PDF、超页数/超大文本、解析超时和临时文件清理；20MiB 业务限制不是解压内存上限。
- 以真实查询计划确定索引与 N+1 问题：病例列表、证据详情、版本回放、job event 流分别用小/中/大 fixture 测响应时间、SQL 数量和内存。没有本轮压测证据，不给出臆测加速比例。
- 保留 append-only、冻结快照和人工审核分离；历史资料补录/纠错不直接覆盖旧账本。

### 3.3 LLM 质量、稳定性和费用建议

本轮两项修复阻止格式错误被写成成功，不等于事实正确性保证。后续分三层落地：

1. **协议层**：propose/assess 统一严格 schema；缺键、错误枚举、无效引用、全量候选被拒绝应与合法空结果区分。记录拒绝计数和原因类别；不要无限 JSON 修复。
2. **运行层**：401/403/400 不原样重试；429/可恢复 5xx 退避并考虑 Retry-After；所有尝试和合规重写共用总预算。当前 SDK timeout 是 I/O timeout，不能当作严格整操作截止时间。
3. **审计层**：记录 input/output tokens、attempt、latency、实际模型/采样参数、request ID 和 run ID，设置每任务/批次预算；不记录密钥、完整带认证 URL 或未经脱敏正文。
4. **证据层**：输入包含引用 ID、时间和原文位置；输出逐断言引用，服务端验证属于冻结证据集合。结论必须同时覆盖支持、反证和缺口；模型不能自行批准自己。
5. **评测层**：建立固定正常/反证/矛盾/资料不足/提示注入/截断/非法 JSON 资料集，分开测抽取有效率、引用连续性、反证覆盖率、拒绝率与人工一致率。在线模型切换前运行同一集合，保留 run 配置与报告。
6. **历史修复**：本次不会自动重跑此前错误 success watermark。先审计疑似错误记录，生成有范围的重抽清单，再以新 run 追加结果，不能直接删除审计历史。
