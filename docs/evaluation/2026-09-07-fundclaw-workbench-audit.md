## 1. 检测对象与结论

本次以用户所指的 **FundClaw 多角色研究工作台** 为基准，而不是主工作区的旧事件/市场页面。

- 界面基准：`docs/prototypes/fundclaw-team-workspace-v2.html`，预览 `http://localhost:63297/`。
- 实施工作区：`<project-root>`，分支 `codex/fundclaw-gateway-p0-plan`；保留此前未提交工作，不将整棵工作树的已有改动计为本次成果。
- 正式前端：`frontend/src/app`、`frontend/src/gateway`、`frontend/src/workbench/Gateway*`。
- 正式后端：`app.gateway_main:app`，Gateway 私有接口、原生研究/采集 worker、证据与报告读取、LLM client。
- 2026-09-06 的主工作区审计不能替代这些文件的验收。本次重新执行测试和浏览器检查。

**最重要的结论：当前已经有可用的真实研究底座，但还没有完整的四专业角色执行系统。** 原型中的产业、财务、策略、AI 质控是产品设计；正式 Gateway 的四个枚举是执行阶段。已有报告与证据链可以复用，不能把这四个阶段改名就宣称多角色实现完成。

本次选择保留三栏研究案头和四专业角色方向，先修确定性缺陷，再按真实任务归属接通角色。只改外观无法兑现角色协作；直接重写整套运行时则会丢失现有范围冻结、幂等、授权和证据准入能力。

## 4. 前端传输与运行可靠性

**FE-01 / P1，已修复：JSON请求无截止时间。** API连接/响应体一直不结束时，提交按钮无限禁用，身份与证据读取也会一直等待。`HttpGatewayClient`新增默认30秒、可配置的JSON完整请求截止时间，包含response.json；保留外部abort、清理计时器和监听器。超时不自动重发写入，也不表示后端取消。原有表单继续保留相同正文的幂等键。

**FE-02 / P2，已修复：SSE断流后退避期间仍显示live。** 现在在等待重连之前立即发布reconnecting，避免把最后状态误认成持续实时更新。

**FE-03 / P2，已修复：取消时等待中的流读取依赖fetch隐式行为。** 现在abort显式cancel reader，解除挂起读取并清理listener。4条新增传输测试修复前全部失败，修复后通过；另有独立只读代码复核。

**FE-04 / P2，待做：SSE握手及静默连接无watchdog。** 当前30秒只用于JSON，SSE收到头后便显示live，半开连接可能永远不再收到chunk。应分别增加握手期限和基于真实heartbeat/chunk的空闲期限；超时从最后确认游标重连。不能给整个SSE设置30秒总超时。验证服务器不回响应头、只回头无body、持续心跳、权限撤销及慢网络。

**FE-05 / P2，待做：服务端20,000字符限制缺少表单对应提示。** 超长输入被422拒绝时当前泛化为“送达未知”。应前端显示明确字符限制且保留完整输入，服务端继续强校验；区分确定验证拒绝与网络结果未知。不要静默截断研究材料。

**FE-06 / P2，待做：刷新后未知提交的恢复契约。** 同页重试保留幂等key已有测试，刷新/路由卸载的key仅内存保存，不能直接宣称跨刷新exactly-once。应设计不存敏感正文的pending fingerprint/key记录、明确用户确认相同请求与后台receipt查询；检查原子创建、未知结果、重复key/不同正文冲突。

## 5. 后端、数据隔离与性能

**BE-01 / P1，已修复：稳定历史每次重新进入幂等写入路径。** adapter在会话锁内一次读取本轮已持久化source_key，新事实仍走原仓储；集合只在本次事务内使用，不缓存权限。4161条合成原生事件形成4170条角色事件，重复快照20880→51 SQL、3.597→0.280秒；空replay 20880→51 SQL、3.268→0.297秒。首次补建37544→37545 SQL、5.851→5.733秒，**首次补建没有得到本次改善**。这些是单次本机SQLite测量，非真实用户案例或SLA。

**BE-02 / P2，待做：全历史快照与事件读取仍O(N)。** 将增量事件和当前获授权artifact集合分开读取，再以SQL游标分页；每次仍验证owner、tenant、run、cutoff、来源展示权。只加after_sequence过滤会漏掉旧引用权限撤销，不可直接这样改。

**BE-03 / P2，待做：首次历史补建逐条持久化。** 为大历史建立后台catch-up/批处理，保持conversation/run双序号、唯一source_key、故障回滚和多worker竞争。以5000/50000事件、10/50观察者测P50/P95和数据库锁等待。

**BE-04 / P2，已修复：私有响应缓存策略不统一。** HTTP实测列表/快照没有`Cache-Control`，而证据/报告已有`no-store`。现在在专用Gateway入口统一对列表、身份、创建回执、快照、受控错误和SSE设置`Cache-Control: no-store`。7项用例先因缺响应头全部失败，修复后相关API/隔离/授权/SSE共68项通过。此次证明的是缓存契约缺失及其修复，没有证明曾经发生缓存泄露；客户端的`cache: no-store`不能替代服务端契约。

已有保护经针对性回归复核：私有主体/tenant隔离；原生Case授权；source contract到期隐藏历史引用；跨run/伪造artifact拒绝；幂等重放与payload冲突；过期lease恢复；worker完成前后事务与终态竞态；安全SSE不含原文、提示词或provider异常。新增测试包含真实文件SQLite双Session/线程、事务回滚后重投影、追平后owner/tenant/admission撤销。

**部署边界仍然重要：** `gateway_main`使用独立数据库及窄路由；Vite同源身份代理仅用于回环单人环境，不能当多人登录系统。生产/preview不会自动提供本地代理。后续部署需把真实认证、用户映射、SSE不缓冲、DB迁移/备份恢复、worker readiness和服务启动文档纳入发布门槛。未将现有工作区服务公开到外网。

完整证据与重现命令见[后端专项报告](2026-09-07-fundclaw-backend-audit.md)。

## 6. LLM调用与研究质量

**LLM-01 / P1，已修复：永久错误重复请求。** 400/401/403/404/422和未知SDK错误立即转固定安全异常；连接/超时和408/409/429/5xx仍按原预算重试。新增25项离线用例，红阶段11失败/14通过，客户端合并44通过，扩展引擎/准备生成器119通过。错误文本不暴露上游响应，异常cause保留供受控诊断。

| ID/优先级 | 已验证缺口 | 修改建议与验收 |
|---|---|---|
| LLM-02 P1 | 无统一输入预算及输出token cap | 每操作定义预算，模型配置明确cap参数；分块保留span映射，超限拒绝或显式分块，不裁掉反证；测试超长、空输入、单个巨型表格 |
| LLM-03 P1 | JSON repair后只保证dict；不消费finish_reason/refusal | 各操作严格schema、枚举/长度/集合上限；length/refusal失败；repair单独审计。截断但可修复JSON不得冒充完整结论 |
| LLM-04 P2 | 可重试错误立即重发，无总deadline/backoff/jitter | 上游Retry-After有上限，注入时钟测试；区分LLM重试与采集job重试，避免预算相乘失控 |
| LLM-05 P2 | usage/model/request_id等被丢弃，AIRun仅操作级 | 新增attempt账本，累计成功/失败/rewrite资源；缺失usage显示unknown，费用由版本化价表计算，不能写零或猜测价格 |
| LLM-06 P2 | 提示词不可信输入规则各操作不一致 | 统一材料是数据的规则，引用/授权由程序强检；加入恶意来源、伪造系统提示、错公司/期间/单位fixture；真实模型抗注入效果需单独测 |
| LLM-07 P2 | max_attempts缺整数/极值上限校验 | 拒绝bool/float/极大预算；timeout/temperature等校验有限值；保留显式配置报错 |
| LLM-08 P1功能缺口 | 专业角色未真实调用与交接 | 各角色明确输入/输出schema、工具范围与预算；质控只读前三者产出，不持有人审发布能力 |

研究质量不能用“JSON能解析”“任务succeeded”或“3个支持判断”代替。建议建立固定评测集：引用ID与原文对齐、错期间/错公司拒绝、币种与单位转换、财务同比计算、数字未知不补值、反证保留、来源独立性、合规重写事实不变、质控发现冲突、缺证降级。财务数字计算优先确定性代码，LLM负责解释和提出待核验假设。

现有抽取会检查span归属/逐字引用，提议检查输入statement ID，准备生成器已有120000字符等限制，模型调用前结束读事务且写入前验证输出槽。这些保护应保留，不能因统一客户端重构丢掉。详见[LLM专项报告](2026-09-07-fundclaw-llm-audit.md)。

## 7. 依赖与开发环境
