## 已确认并修复

### P1：JSON 修复掩盖截断或拒绝响应

- 修复前证据：`backend/app/ai/client.py:180` 直接读取 message.content，并在 JSON 失败后交给 json_repair，完全不检查 finish_reason/refusal；`backend/app/ai/assessment_gen.py:166` 随即使用 conclusion、rationale，gaps 缺省为 []。
- 离线复现：构造 finish_reason=length、content=`{"conclusion":"supported","rationale":"partial`，旧 client 返回 `{'conclusion': 'supported', 'rationale': 'partial'}`；截断 `{"statements": []` 同样变成合法空结果。因而模型未生成完的反证、缺口或其余原子陈述会丢失，后续有可能持久化部分结果。现有 provisional/人工审核边界降低误发布风险，但没有修复丢失信息本身。
- 修改：`backend/app/ai/client.py:180–192` 在修复 JSON 前要求 finish_reason 为 stop，拒绝非空 refusal，使用既有固定安全错误。缺少 finish_reason 同样失败关闭。可选 refusal 字段允许缺省，stop 的 Markdown 包裹兼容仍保留。
- 回归：`backend/tests/test_ai_client_determinism.py:241` 起覆盖 length/content_filter/tool_calls/function_call/None/unknown、合法 JSON 搭配 refusal、正常 Markdown JSON 及可选 refusal 缺省。现有 MagicMock fixture 补全真实协议的 stop/refusal=None。
- 风险：省略 finish_reason 的非标准 OpenAI-compatible 服务将不再被接受，需要供应商遵守完成协议。没有真实供应商验证。stop 但 JSON 本身残缺的情况仍保留原来的 json_repair 行为，此次不重构兼容层。

### P2（已修复抽取字段边界）：缺少必需键的抽取结果被记录为成功，并阻止自动重试

- 修复前证据：`backend/app/ai/extraction.py:155` 使用 result.get('statements', [])；`backend/app/ai/proposal.py:114` 对 links 同样缺省为空列表。`backend/app/ai/extraction.py:228–251` 将空抽取记为 success；`backend/app/scripts/run_ai_engine.py:49–78` 用成功抽取 watermark 排除再次抽取。
- 触发：供应商返回合法但错误 schema 的 `{}`（即使 stop），或者所有陈述都因为不存在的 span/无效 quote 被跳过。无法区分“来源没有事实”与“供应商格式错误”，文档可能永久失去自动补抽机会。
- 修改：`backend/app/ai/extraction.py:159–164` 要求 statements 为显式 list，缺失、null、object、string 抛安全 LLMMalformedResponseError，由既有回滚/failed AIRun 路径处理。合法 [] 保留 success watermark。回归在 `backend/tests/test_ai_engine.py:84–118` 验证失败状态、零候选及无成功 watermark，并验证明确空列表仍有成功 watermark。
- 剩余建议：propose/assess 和数组元素仍可采用统一、明确的 schema 验证；输出全部无效时记录拒绝计数并采用独立状态/失败策略。研究准备模块已有严格验证模式可复用。本次未改变数组元素容错、提案服务或既有历史 watermark，不自动重跑先前误记成功的数据。

## 尚待处理

### P2：重试未区分永久错误，也没有退避

- 证据：`backend/app/ai/client.py:172–178` 捕获整个 OpenAIError/httpx.HTTPError 类并立即继续，所有错误采用同样策略。
- 离线复现：fake completion 每次抛 AuthenticationError(status=401)，默认设置调用了两次后才抛 LLMProviderError。无网络、无密钥。
- 影响：401/403/400 等不应原样重试；429/503 立即重试通常无法恢复，反而增加限流压力。传输超时后重发还可能产生重复供应商计费。
- 建议：分类永久错误、429/可重试 5xx 与 transport failure；仅瞬态错误退避重试，尊重 Retry-After，在总预算内加抖动。记录尝试次数及失败类别，但不记录上游正文。
- 已有保护：默认最多 2 次，SDK max_retries=0，避免两层隐式重试；编程错误不被伪装成网络错误，已有测试覆盖。

### P2：所谓“hard per-request limit”并非完整操作截止时间

- 证据：`backend/app/ai/client.py:94–97` 声称 hard per-request limit，但 `:163–178` 仅传 SDK timeout 并执行最多 N 次。已安装依赖 `backend/.venv/lib/python3.13/site-packages/httpcore/_sync/http11.py:196–218` 为每次读取应用 read timeout，没有全局倒计时。
- 影响：阶段性 socket timeout 和整个操作耗时不同；上游持续少量输出可让一次响应超过 90 秒，多次尝试和合规 rewrite 再累加。不能以此证明同步工作器有硬截止时间。
- 建议：明确文档为 I/O inactivity timeout；需要硬上限时加 monotonic 总 deadline，并在所有尝试/重写中共享剩余预算，结合可取消请求或隔离工作器。不要使用不能终止底层调用的单纯线程 wait timeout 冒充取消。
- 已有保护：抽取/提案/评估在 provider 前释放只读事务；acquisition 默认 1800 秒 lease，长工作单元前续租并有落库 fencing。但这些不替代请求 deadline。

### P2：CLI 未捕获异常链可能泄露上游详情

- 证据：`backend/app/ai/client.py:178` 使用 `raise ... from exc` 保留 cause；`backend/app/scripts/run_ai_engine.py:131–136` 等错误路径提交安全 AIRun 后原样抛出，`:246–247` 直接 main()，无顶层安全输出边界。
- 影响：固定 str(error) 和数据库字段是安全的，但未捕获异常的 Python traceback 默认输出完整 cause。上游异常可能包括带 token 的 URL、响应正文，若 CLI stderr 被采集为日志，安全字符串测试无法保证日志脱敏。此结论来自异常传播路径，不声称当前日志已经泄露真实凭据。
- 建议：CLI 顶层捕获已知 provider/domain 失败，仅输出固定类别、运行 ID 并非零退出；必要诊断走显式受控脱敏通道。测试 subprocess/stderr 或 traceback rendering，不能只断言 str(error)。

### P2：传统抽取与评估缺少统一上下文/输出预算和成本计量

- 证据：`backend/app/ai/extraction.py:127–143` 将所有叙述 spans 合并；`backend/app/ai/assessment_gen.py:141–160` 合并全部可见 links；`backend/app/ai/client.py:163–169` 不设输出 token 上限；`:180–222` 丢弃 usage、请求 ID、供应商实际模型等；`backend/app/ai/runs.py:19–44` 没有 token/尝试次数/成本参数。
- 影响：长文或证据累计可产生超上下文错误/大量输出；调用成本与重试放大无法按研究任务归因。没有在线账单证据，不能给出实际金额。
- 建议：统一输入 token/字符预算，必要时分块并保证证据全量覆盖；按供应商能力配置输出限额；将 input/output tokens、attempt、latency、request ID 与 run ID 关联，设置每任务/批次预算。
- 已有保护：研究准备模块 `backend/app/ai/research_preparation.py:53–57,372–378,509–529` 有上下文总字符和字段长度限制；表格先走确定性抽取；成功抽取 watermark、内容质量过滤和 thesis 相关召回减少无效调用。不能将“完全没有成本防护”作为结论。

### P3：评估追溯是输入集合级，尚非逐断言证据引用

- 证据：`backend/app/ai/assessment_gen.py:136–151` 将 evidence_link_ids 存入审计，但给模型的链接只有 role/reason/statement_text，没有逐条 ID、来源等级/原文定位/时间范围；prompt `backend/app/ai/prompts.py:89–108` 却要求考虑来源、时间、范围并完整列反证。
- 影响：可证明评估使用了哪组证据，却不能自动验证每句 rationale 引用了哪个证据、是否确实覆盖反证；未发送的属性无法可靠要求模型考虑。
- 建议：输入加入可核验引用 ID 与实际需要的来源/时间字段；输出分开 supports/contradictions/gaps 并携带引用 ID，服务端验证引用在冻结集合内。文字语义和归因仍需评测及审核。
- 已有保护：snapshot 冻结显式 prompt_link_ids；protocol gate 前后重检；候选引用连续切片校验、来源 authority 降级、人工/不可变自动准入决策以及 evidence proposal review 边界，阻止模型随意发布正式证据。

### P3：配置与可复现性记录仍可加强

- 证据：`backend/app/ai/client.py:70–73` 只校验 timeout/max_attempts，temperature 未校验有限值或范围；`backend/app/ai/runs.py:19–44` 只持久化请求 model_version/prompt_version 等，不包含 temperature、seed、实际响应模型或 fingerprint。
- 建议：启动时验证温度、model 非空、重试合理上限；按运行记录必要采样参数和实际返回模型元数据，避免仅凭 temperature=0 宣称严格确定性。无需记录 API key 或带认证信息的 URL。
- 已有保护：非 test 环境无 key 会 fail closed；pytest conftest 主动清除 provider 环境变量，测试 mock 不会走 live client；temperature=0 与可选 seed 已有回归。

## 后续实施：重试与严格输出边界

本轮已实施此前列出的客户端重试/配置问题，以及 propose/assess 的结构校验。以下记录覆盖前文“尚待处理”中的对应条目；其余建议仍待处理。

- HTTP 400/401/403/404/422 等永久失败不再重试；408/409/429/5xx 与连接/传输超时才允许重试。OpenAI SDK 与 httpx 异常使用相同分类，编程错误仍原样抛出。
- 采用有限指数退避及抖动，并遵守 Retry-After 秒数/HTTP-date；请求等待超过 30 秒或剩余预算时直接失败，不提前于供应商要求重新发送。SDK 隐式重试仍关闭。
- 新配置 `LLM_RETRY_BUDGET_SECONDS` 默认 180 秒（0.001–600），约束**一次 chat_json 的全部尝试及等待**；每次请求只得到剩余预算和 socket timeout 两者的较小值，已过预算的返回不被接受。同步调用不能被这个机制硬取消，晚返回检查也不能撤销供应商计费。后续补充的 operation context 将一次 assessment 及合规 rewrite 共享同一 deadline（见下）；跨整个研究任务的预算与硬取消仍是后续工作。
- 配置校验：temperature 有限且 0–2，timeout 0.001–300 秒，attempts 必须整数 1–5，model 不允许空白，seed 为有符号 64 位整数，预算必须有限；修正文档中“hard per-request limit”说法。
- `app/ai/output_schema.py` 在业务持久化前校验必需字段与列表元素：propose 必须显式 links，每个元素必须有 source_statement_id、合法 role、reason、dict scope；assess 必须显式合法 conclusion、字符串 rationale、字符串列表 gaps。Pydantic 严格类型防止数字被强制转成字符串；固定 LLMMalformedResponseError 不携带输入值的异常链。
- 错误结构现在记录 failed AIRun，不能产出 Proposal、AIAssessment 或 EvidenceSnapshot。合法的空 links/gaps 仍可表达“没有内容”，未知引用 ID 的既有过滤行为未重构。
- 红测：新增重试/配置 15 项先全部失败（包括永久错误重复请求）；schema 9 项先复现缺失输出错误成功/类型异常后修复。更新一项旧测试的错误契约，由泄露实现细节的 KeyError 改为专用 malformed response 错误。
- 最终定向验证：`tests/test_ai_engine.py tests/test_ai_client_retry_policy.py tests/test_ai_client_determinism.py tests/test_compliance.py tests/test_research_preparation_generator.py` **155 passed**；F821 与 diff whitespace 检查通过。全部离线 fake provider，无真实网络请求或密钥读取。

后续优先处理 CLI 安全异常边界、跨调用共享 deadline 与取消、调用预算/usage 审计；再用冻结证据集验证逐引用正确性、反证覆盖率和不同供应商兼容性。保持离线契约测试，只有明确授权的独立 online smoke 才使用真实供应商。
