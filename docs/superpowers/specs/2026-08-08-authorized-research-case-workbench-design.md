# 多入口资料与持续研究驱动的 ResearchCase 工作台设计

本规格的完整产品背景、已确认边界、原型验收合同、现有代码接点和分阶段改造目标见 [Research Operating System 基线蓝图](../../design/2026-08-08-research-operating-system-baseline.md)。后续变更须在该基线的变更记录中追加说明。

## 目标

将 Fund Engine 的主工作面收束为一个可由事件、新闻、外部研报、聚源等授权来源、粘贴内容或上传文件启动并持续验证的 `ResearchCase`。研究员打开页面时应立刻知道：当前判断、为什么尚不能或能够下结论、自己唯一应做的动作，以及完成该动作会推进到哪一步。

这不是研报摘要页、普通待办列表或金融终端。它交付的是有原文、反证、人工审核和时点边界的研究判断。

## 用户与首要动作

主要用户是日常处理新材料、审核 AI 提议、维护行业判断的行业研究员。

默认首要动作是**审核会阻塞结论的关键证据**。只有当不存在此类审核时，页面才依次引导用户：复核可能改变已发布结论的新材料、确认竞争性命题范围、或等待系统补证据。普通新材料不得抢占主动作。

每个动作必须同时说明：

1. 当前为什么需要该动作；
2. 用户需要做什么；
3. 完成后将解锁什么研究状态。

## 产品边界

- 首批仅服务少数高信息密度行业；事件、新闻、外部研报、聚源等授权来源、粘贴内容和上传文件均可作为研究入口或补充资料。
- 聚源是高质量且授权清晰的来源适配器，不是唯一入口；不同资料类型必须保留不同的许可、冻结与可采纳状态。
- 一篇研报是 `research_opinion` 或候选命题来源，不是最终事实或最终结论。
- 最终判断仅允许为 `supported`、`contradicted`、`insufficient_evidence`；AI 草案必须可见地标为未经人工复核。
- 不做全市场信息流、自动交易、自动推荐或把基金披露说成实时持仓。
- 图谱仅用于下钻证据与影响路径，不作为首页主角或可信度替代品。

## 视觉方向

采用“静谧证据案头”方向：研究员在安静办公环境中阅读授权材料、准备判断与复核，而不是盯盘或浏览信息流。

- 色彩策略：克制。暖灰纸面与深石墨文字为基底；低饱和苔绿色用于已审核/可执行，砖红仅用于反证、风险或阻塞；蓝色仅用于链接和聚焦。
- 字体：系统无衬线体，数据与定位信息紧凑，结论和原文阅读保持舒适行长。
- 参考：Quartr 的一手材料阅读与出处并置；AlphaSense 的变化为何重要和持续跟踪。不得复制其品牌、内容或界面。
- 不使用大号指标卡拼格、装饰性图表、玻璃效果、渐变文字或默认聊天入口。

## 信息架构

### 全局入口

产品首先进入“研究调度”，而不是全量指标仪表盘或某一个 Case。它用“今天，先推进哪一个判断？”组织多个独立 Case：优先显示会阻塞结论、可能推翻已发布判断或需要确认范围的事项，其余 Case 只显示当前系统工作和最近更新。创建研究时提供“从事件开始”与“导入/粘贴资料”两个入口；资料先进入收件箱，研究员可选择归入已有 Case 或创建新 Case。顶部保留“待我处理”入口，用于在多个 Case 存在时按决策影响排序；从该入口进入后，始终回到具体 Case。

单个 Case 工作台不是首页。它显示一个研究问题、当前版本、专属证据、审核、结论与持续研究；标题区提供 Case 切换器和“返回研究调度”。切换 Case 不得带入另一 Case 的结论、审核状态、版本或未审核提议。

### Case 稳定导航

左侧导航固定为：

1. 结论；
2. 命题与证据；
3. 原文资料；
4. 审核；
5. 市场与表达；
6. 监控与版本。

导航显示必要数量，例如“审核 2”，但不以红点制造焦虑。每个页面都保留当前判断与返回当前动作的路径。

### Case 关联

多个 Case 可以通过 `CaseRelation` 关联，关系类型仅限：`shared_driver`（共享驱动）、`follow_up_validation`（后续验证）、`potential_conflict`（可能冲突）和 `shared_material`（共享资料）。每一条关联必须有理由、创建人、审核状态和时间；AI 只能提出关联候选。

关联边用于帮助研究员发现相关工作，不是证据、结论或审核结果的继承机制。共享资料可被另一个 Case 引用，但在成为正式证据前，仍必须在目标 Case 中重新确认来源权限、范围、证据角色与人工审核。单个 Case 的右侧显示少量已审核关联；完整网络只作为下钻页，不能替代首页调度或 Case 内证据阅读。

### Case 首屏

中间主阅读区依次呈现：

1. 研究范围、截止时点与授权材料状态；
2. 当前判断，含 AI/人工状态和“不构成投资建议”边界；
3. 主要反证和关键缺口；
4. 竞争性命题，逐条显示支持、反驳、范围和下一验证事件；
5. 证据时间线与授权研报摘要。

右侧“证据与行动”栏始终可见，包含当前阶段、主动作、解锁结果和少量次级动作。它不展示内部任务 ID、JSON 或 worker 预算。

## 关键交互流程

### 1. 审核关键证据

触发：存在可采纳、属于当前范围且会阻塞结论的待审证据。

1. 用户点击“审核 N 条关键证据”；
2. 页面进入左右分栏：左侧为冻结原文及精确 locator，右侧为 AI 提议、命题、支持/反驳角色、范围和历史审核；
3. 用户选择确认、驳回或要求补充，并必须填写审核理由；
4. 提交后立即显示下一条和已完成进度；
5. 完成后返回 Case 首屏，明确显示“已解锁结论草案”或“仍需补充何种证据”。

默认不提供高风险的批量通过。键盘可执行前进、返回和查看原文定位。

### 2. 阅读、归档和引用资料

触发：用户点击新闻、研报、上传文件、粘贴快照、引用、证据时间线或任何“定位到原文”。

阅读面板必须显示：来源类型与提供方、发布日期、获取时间、内容版本、许可范围、解析状态和精确文本位置。正文高亮当前引用，可展开相邻上下文。若系统仅保存文本快照而没有原始 PDF，界面必须诚实写为“内容快照”，不能称作原件 PDF。聚源资料额外显示“聚源授权”及其合同适用范围。

用户可从一段原文发起“纳入当前命题候选证据”，但这只创建待审核提议，不能直接改写正式结论。

### 3. 新研报可能改变结论

触发：一份新授权材料与已发布 Case 的命题、关键指标或反证条件相关。

1. “待我处理”只显示影响摘要、变化来源和可能受影响结论；
2. 用户点击后进入“变化比较”，左侧是已发布结论与原有依据，右侧是新研报/公告的精确变化；
3. 用户选择“纳入重新复核”或“记录为不改变当前判断”；两者都需要理由；
4. 前者创建新版本研究范围，旧版本结论保持可回放；后者保留审计记录和后续提醒条件。

### 4. 持续研究与立即补证

研究员可为每个 Case 设置 `CaseMonitor`：关注的命题/公司/关键词、允许资料源、检查频率、下一验证事件、预算上限和暂停状态。默认监控范围只覆盖当前 Case；没有明确范围和下一验证事件的 Case 不能启用定时补证。

“立即补证一次”是显著但受控的操作。它创建与定时运行完全相同的 `ResearchRun`，只使用该 Case 的监控范围和许可允许的资料源，不直接改变结论。运行中，卡片显示阶段、已检查资料源、已冻结材料数、提出的支持/反证/范围不一致候选数、失败原因和预计下一步；完成后保留可回放运行记录。

运行结果只会落入以下三种用户状态：

1. 无关键变化：记录本次检查、检查口径和下一次时间，原判断不变；
2. 发现关键待审材料：Case 主操作改为“审核 N 条关键证据”；
3. 可能影响已发布结论：Case 主操作改为“查看并决定是否重新复核”。

调度器（例如 OpenClaw）只负责领取到期 `CaseMonitor`、重试和通知，并调用受控运行接口；它没有直接发布结论、写基金暴露、执行交易或绕过来源许可的权限。

只有经过审核的传导关系才进入公司、股票与基金披露视图。基金条目显示报告期、披露日、采集日、覆盖率、来源和过期状态。页面的操作是“设置下一验证事件/监控条件”，不是“买入/卖出”或“一键加入组合”。

## 研报验证、关键因素与市场表达

研究的终点不是停在行业或公司叙事，而是形成可复核的“研报主张是否正确、对哪些公司/股票产生何种有条件影响、哪些基金披露暴露于这些股票”的表达链路：

`ReportClaim → KeyFactor → ClaimVerification → Company / Stock → HoldingDisclosure → Fund`。

### 研报主张与关键因素

任何进入验证链路的研报主张还必须通过 `MetricRegistry + MechanismTemplate + ResearchabilityGate`。结果变量、目标实体/业务范围、方向、基线、时间窗、模板版本和反证规则均须由研究员确认并冻结；AI 只能以原文定位提议候选。完整对象、首个“海外 AI CapEx 到中国硬件公司”模板、节点角色和拒绝条件见 [固定结果变量与机制模板设计](2026-08-08-metric-and-mechanism-template-design.md)。

每份研报必须先经过版面和抽取质量主链路，再产生 `ReportClaim` 候选：`Docling + PP-Structure` 负责页码、段落、表格、单元格和阅读顺序；LLM 或 PP-UIE 只产生 `AtomicClaimCandidate`；候选必须通过逐字连续 quote 的 offset/hash、数值、单位、期间、主体和来源权威性校验，并通过版本化金标回归与人工审核，才可写入正式 `SourceStatement`。解析器、模型或提示词升级不能直接覆盖既有结果，必须留下独立候选/运行版本并通过回归门禁。

`AtomicClaimCandidate` 至少保留逐字 quote、精确 locator、文档与 quote hash、主体、谓词、对象或数值、单位、期间、适用范围、断言者、主张性质和机器校验结果；一次候选只包含一个可独立判断的主张。通过审核的正式 `SourceStatement` 可被用来提出 `ReportClaim` 候选。该候选必须保留精确原文定位、主张类型（`disclosed_fact`、`forecast`、`research_opinion`）、涉及实体、观察期和提出者。研报主张不是事实，只有原文所说的内容可被审核确认；预测和研究观点必须始终保留其性质。

券商研报对公司披露的转述仅是二手转述，不能自动归入 `disclosed_fact`。只有已冻结、获准使用的公司公告、财报或原始数据可作为对应的一手证据时，才能由审核人员建立关联并采纳为已披露事实。关键因素、股票/基金表达和正式结论使用的陈述必须人工审核。

每一个将进入验证链路的研报主张必须对应一个或多个 `KeyFactor`。关键因素至少定义：名称、预期方向、适用公司/股票、可验证指标、允许数据源、验证窗口、支持/反驳条件、下一验证事件、审核状态和理由。例如“云厂商 CapEx 增速”“订单与交付窗口”“ASP / 毛利率”“EPS 预期差”是因素，不得用笼统的“利好/利空”代替。

`ClaimVerification` 只允许为 `supported`、`contradicted`、`insufficient_evidence`、`not_due`。持续研究和“立即补证一次”围绕明确的关键因素领取任务，并产生待审核资料或观测，不能自动确认研报主张或改写正式结论。

### 基本面、市场观测与基金表达

“市场与表达”页以同一条影响路径展示三种不同证据：

1. **基本面影响**：订单、交付、收入、ASP、毛利率、EPS 修订或估值等，必须通过已审核的传导关系与公司/股票相连；
2. **市场观测**：记录资料可得时间、事件时间、T0/T+5 等事件窗口、基准、价格来源、盘后处理和相对表现。它描述发生了什么，不能自动写成“研报或因素导致股价上涨/下跌”；
3. **基金披露表达**：只展示经审核关系命中的股票及基金的历史披露持仓，必须同时显示报告期、披露日、采集日、来源、覆盖率和过期状态，绝不表示实时仓位。

用户在此页优先看到当前影响判断、关键因素状态和最大缺口，再下钻到公司/股票数据、事件窗口和基金暴露。右侧检查器显示当前因素的研报主张、验证指标、时间窗、支持/反证数、数据许可与下一验证事件；“立即补证此因素”只用该因素允许的数据源创建一条受控 `ResearchRun`。

聚源等供应商可作为研报、公告、新闻、行情、基本面或基金数据的适配器，但每类数据能力必须按实际授权工具和可用字段确认后才能启用。原始响应、工具/接口标识、获取时间、内容/数据 hash 和合同版本须随数据保存；不得因已有研报授权而推定具备基金持仓、实时行情或导出权限。

## 状态与文案规则

| 状态 | 用户看到什么 | 主动作 |
| --- | --- | --- |
| 首次进入、尚无 Case | 授权研报如何启动研究，已支持的行业范围 | 从聚源研报创建 Case |
| 系统补证据中 | 正在核验的命题、已检查材料和下一次检查时间 | 查看研究依据 |
| 关键证据待审 | 阻塞的判断、待审数和解锁结果 | 审核 N 条关键证据 |
| 可形成草案 | 草案的证据边界、未决不确定性 | 复核结论草案 |
| 已发布、出现相关新材料 | 新材料与既有结论的差异 | 查看是否需要重新复核 |
| 无法下结论 | 已检查的竞争解释与明确缺口 | 调整命题或补充来源 |
| 已启用持续研究、无变化 | 上次检查范围、运行摘要与下一次检查时间 | 立即补证一次 |
| 定时运行中 | 当前阶段、已检查来源、材料/提议数量与失败情况 | 查看本次运行 |
| 研报主张待验证 | 关键因素、指标、验证时间窗和最大缺口 | 立即补证此因素 |
| 基金披露过期或覆盖不足 | 受影响股票、最后披露期和缺失范围 | 查看数据状态 |
| 来源或许可不可用 | 哪项许可/内容/解析失败，不泄露不可见内容 | 查看来源状态或联系数据管理员 |

加载采用骨架屏；空状态指导下一步；错误状态保留可重试或回到原文的路径。颜色之外必须同时使用文字与图标表达支持、反驳、待审和已审核。

## 资料许可与可复现性

每份资料在进入可检索、AI 处理、导出或 API 前，必须由 `SourceContract` 或同等的用户上传/粘贴使用声明授予相应权限。该记录至少说明来源类型、供应商或上传租户/团队、是否允许 AI 处理/展示/导出/API、地域、有效期、保留/删除策略与下游限制；缺项资料可保留为线索，但不得越权处理或采纳。

`ProviderRecord` 必须保存供应商资料的具体记录标识、请求口径、原始响应或可重取凭证、内容 hash、获取时间与合同版本。上传文件需保存 blob/对象版本、MIME、上传人和保留策略；粘贴内容需保存原文、粘贴人、可选原始 URL 与核验状态。`licensed_provider`、`uploaded_file`、`pasted_snapshot`、`public_url` 是独立来源准入类型，不得把内部标识伪装为公网链接来通过审核。

## 验收标准

1. 研究员进入当前 Case 后，五秒内能说出当前判断、唯一下一动作和完成后的解锁结果；
2. 研究员进入研究调度首页后，五秒内能说出今天最优先处理的研究、其原因和其余 Case 正在做什么；
3. 任意正式结论可回到获准使用材料的精确定位和审核记录；
4. 审核一条证据不需要离开当前流程，提交后明确看到下一条或新的 Case 状态；
5. 新研报不会静默改变已发布结论，所有重新复核产生可回放版本；
6. 每个已启用的持续研究均能显示范围、上次/下次检查、运行记录、产生的材料/提议和失败原因；“立即补证一次”与定时运行使用同一受控路径；
7. Case 切换不混入其他 Case 的结论或待审内容；所有关联均显示类型、理由、审核状态与时间，且关联不会自动采纳证据；
8. 每一条进入市场表达的研报主张都有可定位原文、主张类型、关键因素、验证指标、时间窗和人工审核状态；
9. 股票层将基本面影响与市场观测分开展示；市场观测保留事件窗口、基准、可得时间和价格来源，且不将相关性自动表述为因果；
10. 基金层仅展示报告期披露持仓，并显示报告期、披露日、采集日、来源、覆盖率和过期状态；
11. 各类资料和数据的许可、原始快照能力和展示/导出/AI 处理限制对系统可执行；
12. 未审核 AI 输出、来源不可用、披露过期和证据不足均有明确、不误导的状态；
13. 窄屏下先显示当前判断与主动作，再显示证据和辅助导航；核心审核流程支持键盘和 WCAG 2.2 AA。

## 非目标

- 替代 Wind/聚源的全量数据终端；
- 创建无来源约束的聊天问答；
- 将历史基金披露转化为实时仓位、推荐或交易指令；
- 用研报、事件窗口或关联关系自动断言股票涨跌的唯一因果；
- 使用漂亮图谱或数量统计代替证据、反证和人工判断。
