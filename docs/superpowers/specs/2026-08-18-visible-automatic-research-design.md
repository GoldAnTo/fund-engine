# 自动研究输入与过程可见性设计

## 目标

让研究员在自动研究的每个入口和每个状态中，都能立即回答四个问题：系统正在做什么、已处理多少、接下来做什么、还需要多久。用户不需要理解 `extracting`、`freezing`、`admit` 等内部工作状态。

第一版支持三种等价输入：研究主题、粘贴的已有材料、上传的 PDF、TXT、Markdown 或 CSV 文件。上传文件会被冻结为本次研究的原始材料，并在后续过程和结果中可回看。

## 非目标

- 不支持 Word、Excel 或图片 OCR。
- 不将 Worker 原始日志作为默认界面。
- 不承诺精确倒计时；没有足够进度样本时不伪造预计时间。
- 不改变自动研究的证据准入、来源合同或人工审核边界。

## 用户体验

### 创建

创建页是一个统一输入区：用户可以输入研究主题、粘贴材料，或拖放/选择一个支持类型的文件。选中文件后，页面显示文件名、类型、大小和“会作为本次研究的原始材料”说明。用户只需点击一个“开始自动研究”按钮。

提交前验证空输入、多个文件、未支持类型和超出大小限制。上传或启动失败时保留输入和已选文件，给出可恢复的错误说明。

### 过程

过程页顶部是稳定的研究摘要，而不是泛化的“处理中”：

- 当前动作，例如“正在解析已找到的来源”。
- 当前批次进度，例如“已解析 8/12 条”。
- 下一步，例如“随后校验证据是否可引用”。
- 时间，例如“已用时 3 分钟，预计还需约 2–5 分钟”；未形成估计时写“正在根据当前批次估算时间”。

五个阶段继续保留，但每个阶段显示实际计数、已产生的证据、未处理项目及下一阶段。阶段名称使用用户语言：资料获取、内容解析、证据校验、分析判断、生成结论。

最近活动默认按同类工作聚合，如“正在解析 8 个来源”，并提供“查看技术详情”展开逐条记录及内部状态。技术详情是诊断工具，不能替代摘要。

跳过与异常说明要表达影响和后续行为，例如“29 条来源不满足可引用条件，系统已继续寻找替代来源”，而不是显示 `admit` 或内部异常码。

### 详情与结果

自动研究过程页、事件工作台和研究结果页使用同一研究摘要。用户可回看输入材料、处理过的来源、被跳过或失败的项目及原因、自动纳入的证据和最终结论。所有自动结论和自动纳入证据继续显著标注“系统自动生成，未经人工审核”。

## 关键因素判定

自动研究不能把模型最先提到的候选因素直接称为关键因素。候选因素先进入冻结范围，并分别接受四道可追溯的判定：

1. **相关性**：因素必须直接回答本次研究问题，而不是只属于一般背景。
2. **因果影响**：因素必须能解释事件结果、市场反应或后续变化，不能只与结果同时发生。
3. **证据强度**：因素需要满足可引用证据的来源质量、数量和一致性门槛。
4. **反证检验**：存在足以推翻主张的反证、或证据不足时，因素不能标记为关键。

每个因素恰好属于一种分类：关键因素、次要因素、待确认因素或排除因素。关键因素显示判定依据：与研究问题的关系、支持与反证的数量和摘要、证据缺口以及当前置信边界。待确认因素显示系统下一步要补的证据；排除因素显示排除原因。

自动结论中的“首要因素”只能从通过四道判定的关键因素中选择，且按可解释的综合证据强度排序；没有符合条件的因素时，结论必须写明“尚未确认关键因素”，不得把第一个获得支持的候选因素冒充为首要因素。

## 数据与接口

增加一个面向界面的自动研究进展投影，而不是让前端推断 Worker 状态。投影包含：

- `current_action`、`next_action`、`elapsed_seconds` 和可选的 `estimated_remaining_seconds_range`。
- 每阶段的总数、完成数、处理中数、跳过/失败数和可读摘要。
- 聚合活动条目以及可展开的技术活动。
- 面向用户的例外条目，含影响、数量和系统后续动作。
- 输入材料摘要，含主题/粘贴材料/上传文件、上传文件的名称和解析状态。
- 每个候选因素的四道判定结果、支持和反证概览、证据缺口、分类与可解释排序依据。

估时由后端使用同一运行内已完成项目的耗时与待处理数量计算范围；没有足够完成项目时返回空值。前端不得用轮询间隔或静态阶段顺序伪造 ETA。

上传创建沿用已存在的上传材料冻结能力：先创建并冻结文件，再以该原始文档版本启动自动研究。失败必须是原子的，不留下可见的半创建研究。

## 边界与错误处理

- 所有输入类型都经过租户、文件类型、大小和原始材料合同校验。
- 进展计数只能来自冻结范围及经验证的任务/Job；跨运行或过期运行的数据不能显示为当前进度。
- 原始事件只在技术详情中显示，且保留时间、来源任务和可读映射。
- 轮询失败时保留上一次可信摘要，明确显示“暂时无法更新”，并允许重新读取。
- 自动研究失败时显示失败阶段、已完成工作、下一步（可重试或查看原因），不把失败伪装成等待。

## 验收标准

- 用户能从创建页用主题、粘贴材料或单个支持类型文件开始自动研究。
- 用户在任何自动研究页面都能看到当前动作、完成量、下一步和诚实的时间信息。
- 默认活动不展示未翻译的内部状态，也不会被重复事件淹没。
- 用户可展开看到具体来源与技术状态。
- 过程、工作台和结果对同一运行给出一致的输入、证据、异常和审核边界。
- 关键因素必须满足四道可追溯判定；没有满足条件的因素时，系统明确显示未确认，而不是选择第一个支持项。
- 前后端测试覆盖上传、计数/ETA、活动聚合、异常翻译、失败与重新读取状态，以及无障碍状态播报。
