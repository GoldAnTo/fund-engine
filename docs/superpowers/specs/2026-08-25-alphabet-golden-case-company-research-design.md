# Alphabet 黄金案例公司研究设计

日期：2026-08-25

状态：用户已于 2026-08-25 书面通过

## 1. 决策摘要

第一版不再从通用 Company、Industry、Geography 项目体系开始，也不把
InvestmentMandate、ResearchScope、ResearchAgenda 和 RevisionBoundary 暴露成用户要填写的
主流程。产品先用 Alphabet 建立一条从搜索、资料采集、经营分析、预测、估值、判断到版本冻结的
完整公司研究纵向闭环，再从真实闭环中抽取通用公司研究内核，并使用 CATL 验证跨行业、跨市场和
跨币种复用。

用户研究的是 Alphabet 公司；Google 是其主要品牌和业务语境。GOOGL 与 GOOG 是与公司研究关联的
不同 Security，只在经济权利、市场价格和每股价值桥接时分别处理。Industry 与 Geography 在本阶段
是公司经营、竞争、政策和财务传导的上下文维度，不是独立一级项目。

## 2. 要解决的问题

现有新建研究页要求用户逐项填写授权、范围、议程、时间、价格、资本结构、证券权利、来源 ID 和
哈希。它把审计内核误当成用户任务，要求用户先理解系统内部结构，尚未回答“系统如何真正研究一
家公司”。

第一版应证明：专业个人投资者只需选择一家公司，系统就能建立一张可信研究地图，自动准备公开
资料，把业务事实映射到经营变量、财务、情景和估值，诚实呈现支持证据、反证和缺口，并由用户
显式冻结可回放的暂定判断。

## 3. 产品目标

1. 用户搜索“Google”或“Alphabet”后，系统识别 Alphabet Inc.、GOOGL 和 GOOG。
2. 用户一次确认后进入工作台，不填写研究问题、内部 UUID、来源哈希或市场快照表单。
3. 系统生成 Alphabet 公司研究议程并启动受治理的资料准备。
4. 工作台先展示研究地图、准备进度、已确认事实和具体缺口，不假装研究已经完成。
5. 系统建立业务分部、关键经营变量、财务传导、Base/Bull/Bear 情景、DCF 与反向 DCF。
6. 输出可回答性、暂定方向、置信度、价值区间、预期回报区间、最大反证和下一验证事件。
7. 用户确认候选数据和判断后，原子冻结可回放版本；新资料只创建后继版本或候选变化。
8. Alphabet 闭环完成后，用 CATL 验证通用内核，只有验证后才把 Industry Research 提升为独立产品。

## 4. 非目标

- 第一阶段不提供独立 Industry Research 或 Geography Research 项目。
- 不建设全市场公司模板、选股器、排行榜或新闻流。
- 不要求无人值守生成最终投资结论。
- 不把第三方预测静默写成事实，不补造价格、财务数字、来源或哈希。
- 不输出仓位、交易指令或确定性买卖评级。
- 不为了“通用”预先建立尚未被 Alphabet 和 CATL 使用的领域类型。

## 5. 用户流程

```text
搜索 Google / Alphabet
→ 系统展示 Alphabet Company 与 GOOGL、GOOG Security
→ 用户点击“研究 Alphabet”
→ 系统展示默认研究方案摘要
→ 用户点击“开始研究”
→ 立即进入 Alphabet 公司研究工作台
→ 系统准备官方资料、市场和股权数据
→ 用户核对关键事实、候选提取和缺口
→ 系统建立业务地图与关键经营驱动
→ 系统形成财务桥接和机制不同的三种情景
→ 系统运行 DCF、反向 DCF 与必要交叉检查
→ 系统形成暂定判断或 insufficient_evidence
→ 用户显式冻结版本与备忘录
→ 新资料形成候选变化和后继版本
```

新建页只保留两个步骤：选择公司，以及确认系统默认研究方案。默认摘要包含公司与证券身份、5 年
期限、CNY 基准币种、12% 最低要求回报、25% 永久损失边界、当前资料截止时间、研究议程概要和
资料准备状态。高级偏好默认收起；用户不接触来源哈希、资本结构原始字段或证券权利账本字段。

## 6. Alphabet 研究地图

### 6.1 公司与证券身份

- Company：Alphabet Inc.
- 品牌和业务语境：Google。
- Security：GOOGL Class A 与 GOOG Class C。
- 公司事实只维护一份；价格、投票权、证券权利和每股价值按 Security 分开冻结。

### 6.2 业务地图

第一版至少覆盖：

- Search 与其他广告；
- YouTube 广告和订阅；
- Google Cloud；
- 订阅、平台与设备等其他 Google 服务；
- Other Bets；
- 公司层资本配置、股票薪酬、回购、税和基础设施投入。

系统不把分部名称本身当作模型。每个业务模块必须连接收入来源、成本结构、资本需求、关键事实、
经营变量和可证伪机制。

### 6.3 最小经营驱动

Alphabet 黄金案例先控制指标数量，至少建立以下驱动：

- 搜索使用与商业查询强度；
- 广告变现效率；
- 流量获取成本；
- YouTube 使用、广告和订阅变现；
- Cloud 工作负载、收入增长和营业利润率；
- AI 与数据中心资本开支；
- 折旧、基础设施运行成本和自由现金流；
- 股票薪酬、回购和稀释。

驱动必须形成可审计传导链：

```text
来源事实或人工假设
→ 经营变量
→ 分部收入与成本
→ 营业利润和自由现金流
→ 企业价值
→ 资本结构与 Security 权利
→ GOOGL / GOOG 每股价值和 CNY 回报区间
```

### 6.4 行业与地理上下文

Industry 只在能够解释公司经营时进入研究，包括数字广告、云计算、AI 基础设施、在线视频、移动
操作系统和应用分发。Geography 只在能够解释收入、成本、资本开支、监管、税、汇率或市场准入时
进入研究。

系统不得用某一地区的数据解释全球结果，也不得把公司注册地、上市地、收入来源地和监管辖区视为
同一概念。行业与地理上下文可以被后续项目复用，但本阶段不创建独立行业或地理工作台。

## 7. 资料与证据

默认优先级为：

1. 公司监管申报、年报、季报和业绩材料；
2. 公司官方公告、电话会和产品披露；
3. 法院、监管机构和其他官方文件；
4. 方法透明、口径可核验的行业资料；
5. 明确标记的第三方资料和市场预期。

每条进入正式模型的数据必须保存来源身份、原文定位、报告期间、发布时间、首次可得时间、获取
时间、币种、单位、数值性质、来源角色、知识状态和用户确认状态。机器提取先成为候选；冲突来源
并列；缺少、冲突、陈旧或不可比较的数据形成 ResearchGap。

资料准备失败时，项目仍可进入工作台并显示具体失败和重试操作，但不得形成无来源数字或正式判断。

## 8. 情景、估值与判断

Base、Bull 和 Bear 必须由不同机制驱动，不能只对同一预测做比例上下调：

- Base：搜索广告保持韧性，Cloud 增长并改善盈利，AI 投入较高但自由现金流仍可增长。
- Bull：AI 增强搜索与广告转化，Cloud AI 收入和基础设施利用率高于 Base。
- Bear：AI 分流传统搜索或提高单位服务成本，Cloud 增长不足以覆盖基础设施和折旧，监管改变分发或
  业务结构。

估值至少包括情景 DCF/FCFF 和反向 DCF。系统先回答当前价格隐含哪些搜索增长、Cloud 利润率、AI
资本效率和长期现金流假设，再给出无概率权重的 ValueRange；没有校准分布时不得称为概率估值。

判断保存 answerability、direction、confidence 和 publication_status 四个正交维度。关键经营基线、
财务闭合或价值可识别性失败时，结果必须是 `not_answerable`，且方向和置信度为空。

## 9. 产品界面

Alphabet 工作台固定为九个用户可理解的模块：

1. 概览与当前判断；
2. Google 如何赚钱；
3. 关键经营变量；
4. 来源、事实与缺口；
5. 行业、竞争与监管；
6. 财务、现金流与资本配置；
7. 情景、估值与当前价格隐含；
8. 反证、风险与下一验证；
9. 版本、变化与研究备忘录。

工作台顶部显示研究资料准备进度。系统完成某一模块只代表相应候选产物可供核对，不代表研究完成。
后台 Mandate、Scope、Agenda、Boundary 和哈希只在审计详情中按需展开，不占据主要阅读层级。

## 10. 系统边界与模块

### 10.1 公司研究编排器

一个产品级 CompanyResearchInitializer 接收已确认 Company 及关联 Security，按固定策略版本生成默认
授权、范围和议程，创建 WorkspaceDraft，并以幂等键启动资料准备。它隐藏底层细粒度写接口，不把
编排责任留给浏览器。

### 10.2 通用公司研究内核

通用内核只包含被黄金案例实际使用的能力：对象与证券身份、来源与候选事实、分部与驱动、财务
桥接、机制化情景、估值、判断、ResearchGap、草稿、发布和版本回放。

### 10.3 Alphabet 适配层

Alphabet 适配层提供业务分类、指标定义、来源策略、驱动模板和数据映射。它不得绕过通用来源、
时态、审阅和发布门控，也不得把 Alphabet 专属枚举写入通用账本。

### 10.4 异步准备任务

资料获取、解析、候选提取和重计算使用可恢复任务。任务记录输入边界、策略版本、状态、进度、尝试
次数、产物引用和结构化错误。重复请求不会重复创建正式对象；外部失败只保留候选和缺口。

### 10.5 发布服务

发布仍使用现有不可变 RevisionBoundary 与 ResearchRevision 内核。市场、FX、资本结构或证券权利不
完整时可以保存草稿，但不能绕过门控发布。

## 11. 失败与恢复

- Google 搜索解析到多个身份时，必须明确展示 Alphabet Company 和关联 Security，不能静默选错。
- Company 与 Security 关系无效时，在创建项目前失败关闭。
- 官方来源不可用、无权限或无法解析时，保留具体状态和安全重试，不替换成无来源摘要。
- 价格、FX、资本结构或证券权利缺失时，估值和发布保持阻塞；工作台解释缺少什么以及如何补齐。
- AI 或数据提供方失败不回退到 mock，不创建正式事实或判断。
- 双击、页面刷新和响应丢失通过幂等初始化与状态查询恢复，不创建重复项目。
- 历史版本验证失败时显示内部完整性错误，不用当前数据拼装替代。

## 12. 从点到面的抽取规则

Alphabet 完成前，不因为“以后可能需要”增加通用类型。某项能力只有满足以下条件之一才进入通用
内核：

1. Alphabet 完整闭环必需；或
2. CATL 复用时证明它是跨公司共同需要。

Alphabet 专属业务词汇留在适配层。CATL 复用时，搜索广告、TAC、Cloud 等替换为装机量、利用率、
电池价格、材料成本、储能、海外工厂和客户认证；来源、驱动到财务的接口、情景纪律、估值、判断和
版本内核保持不变。

CATL 若迫使通用内核变化，必须记录变化原因，区分真正通用能力与第二个行业的专属适配。只有两个
公司案例都需要复用行业模型时，才设计独立 Industry Research；Geography 同理。

## 13. 测试策略

### 13.1 领域和服务测试

- “Google”和“Alphabet”解析到同一 Company；GOOGL 与 GOOG 保持两个 Security。
- 默认策略为 5 年、CNY、12%、25%，资料截止具有明确时区，策略版本与输入哈希可重算。
- CompanyResearchInitializer 重复调用返回同一项目和任务。
- Alphabet 适配层不能绕过来源、时态、候选确认、财务闭合和发布门控。
- Base/Bull/Bear 由不同机制和参数驱动。
- `not_answerable` 时方向和置信度为空。

### 13.2 集成和端到端测试

- 从搜索 Google 到进入工作台不需要填写内部表单。
- 官方资料准备成功后，业务地图、驱动、财务和估值均能回链到冻结来源。
- 任一外部步骤失败后没有新增正式 ResearchRevision，页面能重试缺失步骤。
- GOOGL 与 GOOG 的公司事实复用，但价格、权利和每股价值引用精确区分。
- 发布版本在重启、恢复和后续资料加入后保持 canonical manifest 和语义输出不变。
- 第二资料截止创建后继版本并解释事实、机制、预测、价值和判断变化。

### 13.3 CATL 复用测试

- 不复制公司研究编排、来源治理、情景、估值、判断或版本服务。
- 仅新增电池行业的指标定义、来源策略、驱动模板和映射。
- CNY A 股无需 FX；Alphabet 的 USD Security 自动冻结 USD/CNY FX。
- 两个案例通过同一工作台模块和发布门控。

## 14. 完成定义

Alphabet 黄金案例完成必须同时满足：

1. 用户从搜索 Google 开始，零内部表单进入公司工作台。
2. 系统形成可核对的业务地图、资料事实、关键驱动和明确 ResearchGap。
3. 至少一个完整财务桥接能从驱动追溯到自由现金流。
4. 三种情景机制不同且财务内部一致。
5. DCF 与反向 DCF 输出可解释的价值和当前价格隐含假设。
6. 判断包含可回答性、价值与回报区间、置信度、最大反证和下一验证事件。
7. 用户能够冻结、导出和回放版本，并在第二资料截止看到 ChangeSet。
8. 外部失败、重试、重启和恢复不污染或改写正式版本。
9. CATL 在不复制通用内核的前提下走通同一公司研究流程。

在这些条件完成前，不能用“已有 Alphabet 页面”“生成了一份文字报告”或“接口能够返回数据”代替
产品完成。
