# 证据优先的公司研究工作台设计

**日期：** 2026-09-03
**状态：** 产品与设计已确认，待书面规格复核
**目标用户：** 希望通过一家公司做深度研究、理解其赚钱方式和底层经营问题的个人投资者或研究员

## 1. 结论

Fund Engine 的下一条产品主线是一个面向单家公司的、证据优先的研究工作台：用户输入公司名称或证券代码，可选输入一个关注问题；系统以可审计资料为基础，产出商业模式拆解、关键经营驱动、三情景预测、条件性价值判断、反证和研究缺口，并将这些内容冻结为可回放的研究备忘录。

产品首先帮助用户**理解公司如何赚钱、什么变量决定经营结果、哪些问题尚不能回答**，随后才呈现 Base / Bull / Bear 预测、价值区间和当前价格所隐含的条件。它不是荐股工具、交易系统、新闻终端或全市场筛选器。

本设计采用“复用现有研究内核 + 新增公司研究编排和阅读层”的方案。证据冻结、来源政策、原子陈述、模型构建、历史边界、不可变版本和回放能力继续由现有底座负责；新增内容只负责把这些能力收敛成普通用户能走完的一条公司研究路径。

## 2. 目标、范围与非目标

### 2.1 目标

1. 用户能从一家公司出发，理解产品/客户、收入与定价、成本、资本占用、竞争位置和最重要的经营机制。
2. 用户能完整查看每个关键事实、假设、模型数字和结论的依据，并回到冻结原文的精确位置和上下文。
3. 用户能看到事实、管理层指引、AI 假设、用户假设、派生计算、未知和反证之间的明确边界。
4. 用户能基于已确认的关键输入阅读 Base / Bull / Bear 预测和条件性价值判断；资料不足时，系统诚实地输出“当前不可判断”。
5. 用户能保存、导出、回放和比较研究版本，而不会让后来资料改写历史时点的结论。

### 2.2 当前范围

- 单一公司及其明确证券的深度研究；公司与证券必须保留独立身份。
- 受治理的资料采集、冻结、证据查看、商业模式拆解、预测、估值、关键输入确认、保存和回放。
- 对一个后续公告、财报或用户修改形成增量研究候选，作为第二阶段能力。
- 提供完整研究备忘录，而不是只有碎片卡片或运行日志。

### 2.3 明确不做

- 自动交易、下单、持仓/仓位管理、组合优化或经纪商接入。
- 确定性买卖指令、综合 AI 评分、单点目标价或伪精确概率。
- 全市场选股榜、新闻流、热门主题、无结构金融聊天主界面。
- 因为需要一个数值而用默认值、最新网页、未授权内容或 AI 编造补全关键输入。
- 在主线稳定前同步扩展事件研究、基金持仓映射、行业百科或多人审批系统。

## 3. 现有能力与设计约束

现有仓库已经具备本主线必须复用的可信能力：

| 现有能力 | 主要实现/契约 | 在新主线中的责任 |
| --- | --- | --- |
| 公司、证券、权利和市场快照 | underwriting product foundation、`ValuationSnapshot` 与市场输入服务 | 确认研究对象，绑定价格、汇率、股本和权利的确切时点。 |
| 来源授权与冻结 | `source_policy.py`、`source_freeze.py`、`SourceContract` | 校验授权、留存模式、可得时间和内容哈希；生成不可变 source manifest。 |
| 公司资料与证据编译 | `company_research_sources.py`、准备 worker、原子陈述和 evidence proposal 路径 | 将授权资料变为可定位、可审阅的来源与证据候选。 |
| 公司建模 | `company_research_model_builder.py`、`company_research_engine.py`、市场输入服务 | 生成业务地图、驱动图、财务桥接、三情景和估值集合。 |
| 可回答性与缺口 | `answerability`、研究边界和候选证据服务 | 对关键缺失、冲突或不可验证条件 fail-closed。 |
| 发布、导出与回放 | `company_research_publication.py`、revision reader/diff | 冻结备忘录及其父输入，支持历史版本阅读和差异比较。 |
| 前端研究与文档阅读基础 | React/Vite 现有 Case、Document、Source Inspector、Versions 页面 | 作为新页面体系的可复用组件和交互基础，而非继续暴露旧工作流术语。 |

这些能力不应重写。新设计只增加稳定的产品编排、严格的前端读模型、证据阅读体验和关键输入确认体验。

## 4. 产品原则

1. **证据先于叙事。** 每个关键叙述都必须能打开证据；漂亮文字不是可信度。
2. **先理解，后判断。** 备忘录先解释公司如何赚钱与什么会改变结果，再展示预测和价值判断。
3. **事实、假设、计算与未知分离。** 任何一个模型输入只能属于一种明确定义的类型。
4. **历史不漂移。** 选定截止日后，之后公开的材料、最新数据库状态和 AI 补充均不能进入旧版本。
5. **缺失不等于零。** 关键基线、价格时点或资本结构缺失时，估值必须停止，而不是生成完整外观的答案。
6. **AI 辅助而非越权。** AI 可以整理、解释、提出待确认假设、生成初稿；不能确认来源事实、化解冲突或删除 Unknown。
7. **页面服务理解路径。** 用户看到的是研究问题、商业模式、驱动、情景、价值、反证和证据，而不是 worker、artifact、manifest 等内部名词。

## 5. 总体架构

```text
公司 / 证券确认
       │
       ▼
CompanyResearchRun（新增产品编排与状态投影）
       │
       ├── 受治理资料与证据 ──► 冻结 source manifest / 原子陈述 / 复核状态
       ├── 研究输入编译 ──────► 事实 / 指引 / 假设 / 计算 / Unknown / 反证
       ├── 公司模型 ──────────► 商业地图 / 驱动 / 财务桥接 / 三情景 / 估值集合
       ├── 可回答性闸门 ──────► 可回答、部分可回答、不可回答及研究债务
       └── 备忘录与版本 ──────► 初稿 / 关键输入确认 / 冻结版本 / 回放与差异
                                    │
                                    ▼
                          7 页公司研究工作台
```

### 5.1 `CompanyResearchRun` 的边界

`CompanyResearchRun` 是新增的应用编排边界，不是第二个证据账本或模型内核。它只负责：

- 创建一次公司的研究运行，冻结研究问题、公司/证券身份、截止日和默认策略版本；
- 以稳定状态推动已有服务，并持久化每阶段可验证的产物引用；
- 汇总阶段进度、警告、可恢复失败和用户待处理项；
- 输出面向页面的严格读模型；
- 在保存时协调关键输入确认和现有发布服务。

它不得直接写伪造事实、绕过 source policy、把候选资料自动升级为正式证据，或在读路径用当前 head 补全已冻结版本。

### 5.2 运行状态

前端只能使用以下产品状态，不能自行从底层 job、artifact 或 worker 字段推断主流程：

| 状态 | 含义 | 用户可见行为 |
| --- | --- | --- |
| `queued` | 已创建、尚未获得执行权 | 显示研究范围和即将执行的阶段。 |
| `collecting_sources` | 正在采集、冻结和审阅资料 | 显示来源进度、替代来源和已识别缺口。 |
| `analyzing_company` | 正在生成商业模式、机制和驱动 | 显示已确认发现和待验证问题。 |
| `building_forecast` | 正在构建财务桥接、情景和估值条件 | 显示哪些输入已齐备，哪些阻塞价值判断。 |
| `generating_report` | 正在编译备忘录初稿 | 可浏览已经认证的产物，不将初稿误称为已保存研究。 |
| `completed` | 初稿可阅读，或已完成保存 | 显示研究结果和保存/回放入口。 |
| `needs_input` | 关键输入、冲突或权限需要用户处理 | 将用户带到明确的输入确认或证据缺口，而不是只报错。 |
| `failed` | 无法安全继续 | 保留已完成只读产物和可恢复原因；不清空历史结果。 |

## 6. 研究输入与证据契约

### 6.1 输入分类

每个进入模型或备忘录的内容必须具有以下唯一类型，并带有其父输入引用：

| 类型 | 必填信息 | 可否编辑 | 规则 |
| --- | --- | --- | --- |
| `source_fact` | 来源、精确 locator、期间、单位、可得时间、内容哈希 | 否 | 原始事实永不被修改；修改数值必须新建假设。 |
| `management_guidance` | 原始披露与前瞻语境、期间、来源 | 否 | 保持前瞻性质，不能伪装为已实现事实。 |
| `consensus` | 提供方、覆盖范围、可得时间、单位 | 否 | 与公司披露和用户假设分开显示。 |
| `ai_assumption` | 生成依据、版本、适用情景、理由 | 是 | 初始为待确认，不能携带伪造来源。 |
| `user_assumption` | 用户、修改理由、期间、单位 | 是 | 覆盖只作用于模型，不改写来源事实。 |
| `derived_calculation` | 公式/代码版本、完整父输入、单位 | 间接 | 任何数值都能重算和追溯。 |
| `unknown` | 缺失/冲突/陈旧/无授权原因及解决条件 | 否 | 不能默认变为零或合理估计。 |
| `counterevidence` | 反向来源或不成立条件、定位和影响范围 | 否 | 必须和支持证据共同出现，不能被摘要省略。 |

### 6.2 证据准入

一条材料只有在下列条件全部成立时，才能作为可采信证据进入模型、估值或已保存备忘录：

1. 来源身份可识别：发行机构/作者、来源 URI 或受许可 provider reference 均可被稳定解析。
2. 授权、AI 处理权、展示权和留存方式与 `SourceContract` 一致；受限来源不伪造为公开 URL。
3. 原件或许可范围内的可验证响应被冻结，记录内容哈希、抓取时间和解析器版本。
4. 发布、首次可得和抓取时间均不晚于本次研究的 historical cutoff。
5. 每个引用具有精确 locator：页码、段落、章节、表格单元格或等效结构化定位，并可呈现必要前后文。
6. 原子陈述已通过适用的复核状态；未复核候选不能冒充已确认事实。

任何一项缺失、冲突或无法复核时，材料只能以**未证实线索**或 `unknown` 的成因出现。它不能进入预测、价值判断或“已引用来源”样式。

### 6.3 证据谱系与阅读体验

一条正式引用必须形成如下固定谱系：

```text
来源登记与授权
→ 冻结原件与内容哈希
→ 精确定位与上下文
→ 原子陈述及复核记录
→ 事实/反证/假设输入
→ 模型计算或备忘录结论
```

用户从任意事实、图表数字、假设或结论点击“查看依据”后，必须能看到：

- 原文摘录、来源机构/作者、发布日期、首次可得时间、抓取时间、内容哈希、授权和留存状态；
- 冻结原件的受许可阅读入口，直接跳转到页码、段落或表格单元格，并显示必要上下文；
- 该材料支持、反驳或限定哪些原子陈述；
- 它进入哪些模型输入、影响哪段备忘录和是否被后续版本替代；
- 无法展示全文时的明确原因与仍可验证的 locator/hash 边界。

“文末若干链接”不构成证据展示。每一处关键判断都必须有就近的、可点击的谱系入口。

## 7. 研究流程

### 7.1 最少输入

用户只提供：

- 公司名称或证券代码；
- 可选的关注问题，例如“海外扩张是否能够改善长期利润率”。

研究截止日、默认研究议程、情景名称、模型策略和估值方法由服务端采用版本化默认策略；这些策略在 run 创建时冻结。

### 7.2 主流程

```text
确认公司与证券
→ 创建研究范围与历史边界
→ 采集、授权校验、冻结和审阅资料
→ 拆解公司如何赚钱及关键经营机制
→ 编译事实、假设、冲突、反证和 Unknown
→ 生成财务桥接与 Base / Bull / Bear
→ 在门槛满足时形成价值区间与市场隐含条件
→ 生成 AI 研究初稿
→ 只确认关键输入
→ 冻结研究备忘录、导出并支持回放
```

普通证据不逐条阻塞初稿。真正阻塞保存或估值的是会显著改变收入、利润率、资本开支、自由现金流、资本结构、折现率、终值、价值判断或核心反证的关键输入。

### 7.3 商业模式到价值判断的链路

1. **商业模式：** 描述业务单元、产品/服务、客户、收入和定价、成本、资本占用、竞争位置与边界条件。
2. **经营驱动：** 明确销量/用户/渗透率、价格、单位成本、产能、费用率、营运资本等变量，说明方向、时滞、适用范围和证伪条件。
3. **财务桥接：** 将经营驱动映射到收入、毛利、费用、税、资本开支、营运资本、自由现金流和每股价值桥接；每一层保留父输入。
4. **情景：** 固定 Base、Bull、Bear 三套相互不同的机制和假设，而不是对同一组数字贴三个标签。
5. **价值判断：** 绑定确切的价格、汇率、资本结构和证券权利时点，计算价值区间、敏感性、反向 DCF/市场隐含条件及相对用户要求回报的条件性比较。
6. **可回答性：** 同时检查经营基线、财务桥接、市场输入、来源质量、反证和研究债务；未满足时只输出可解释的阻塞原因。

## 8. 价值判断边界

允许展示：

- Base / Bull / Bear 的成立条件、预测、价值区间和关键敏感性；
- 当前价格要成立所需的经营、资本或折现条件；
- 与用户声明的要求回报之间的条件性比较；
- 最强反证、永久损失路径、冲突和无法判断的原因。

禁止展示：

- 把一个模型输出包装为确定性的单点目标价或买卖命令；
- 把新闻、价格变动或 AI 置信度直接转成投资动作；
- 关键经营基线、市场输入或资本结构缺失时生成价值区间；
- 用未经证实材料、默认值或 AI 补全来掩盖研究债务。

价值判断是研究理解的延伸，不是自动交易授权。产品不产生仓位、下单或实盘持仓建议。

## 9. 页面体系

页面围绕研究者的理解路径组织。主导航固定为 7 个页面；原文阅读和保存确认采用专用工作面，避免把内部门禁对象暴露成额外页面。

| 编号 | 页面 | 主要内容 | 关键跳转 |
| --- | --- | --- | --- |
| 1 | **研究库** | 搜索公司/证券、开始研究、继续最近研究、研究状态和待处理项。没有新闻流或选股排行。 | 打开或创建某家公司研究。 |
| 2 | **研究概览** | 研究问题、公司/证券、资料截止日、可回答性、运行阶段、三条关键发现、最大缺口和下一验证事件。结果优先，完整日志折叠。 | 跳转商业、预测、价值、证据或待处理项。 |
| 3 | **商业模式** | 业务单元、产品/客户、收入/定价、成本、资本占用、竞争位置、机制、关键 KPI 和反证。 | 任意模块或 KPI 打开对应证据。 |
| 4 | **预测与情景** | 历史基线、驱动树、财务桥接、Base/Bull/Bear 假设、数值变化的影响、待确认输入。 | 从每个数值打开父输入；修改假设后触发可审计重算。 |
| 5 | **价值判断** | 价格/汇率/股本/权利的 as-of、价值区间、反向估值、敏感性、要求回报比较、反证和估值阻塞。 | 打开市场快照、模型输入与相关缺口。 |
| 6 | **证据中心** | 来源清单、来源政策状态、原子陈述、支持/反驳关系、冲突、模型使用谱系和原文阅读入口。 | 打开精确原文阅读器或受影响的模型/结论。 |
| 7 | **备忘录与版本** | 按“边界→商业→预测与价值→反证与下一步”阅读的完整备忘录、确认记录、冻结版本、差异、回放和导出。 | 从每段打开证据；比较严格祖先与后继版本。 |

### 9.1 精确原文阅读器（专用工作面）

从任意引用打开。它展示冻结原件、命中的页码/段落/表格单元格、必要上下文、来源元数据、哈希、授权边界及引用它的主张。若许可不允许全文展示，阅读器只展示被许可的内容与可验证边界，并清楚说明原因。

### 9.2 保存前关键输入确认（专用工作面）

只列出会对预测、价值判断或核心结论产生实质影响的事实、假设、冲突和 Unknown。每项显示当前值、期间、单位、来源/公式、影响范围和操作：确认、编辑、标记未知、接受缺口或补充授权资料。所有阻塞项处理完毕后，才可调用发布服务冻结版本；普通资料不进入这个阻塞队列。

## 10. 新增读写契约

### 10.1 新增持久化边界

新增的表/持久化对象必须只保存编排状态和用户决策，不重复现有证据、模型或版本正文：

| 对象 | 最小字段与引用 | 约束 |
| --- | --- | --- |
| `company_research_runs` | run id、company/security ids、question、basis id、default-policy version、status、idempotency key、阶段时间戳 | 创建后研究范围不可变；新范围创建新 run。 |
| `company_research_run_stages` | run id、stage、attempt、状态、输入/产物引用、错误分类、worker lease | 成功阶段产物不可覆写；恢复从最后一个认证阶段开始。 |
| `critical_input_decisions` | run/revision id、输入引用、决定类型、actor、理由、时间 | 追加式；不编辑原始来源或模型产物。 |
| `company_research_workbench_projection` | run/revision id、已验证的只读引用和页面摘要 | 可重建的读模型；不能成为事实来源。 |

### 10.2 产品 API

在现有 `/api/underwriting/v1` 公司研究 API 之上提供严格 schema 的产品接口：

- `POST /company-research-runs`：确认身份、冻结研究范围并以 idempotency key 创建 run。
- `GET /company-research-runs` 与 `GET /company-research-runs/{id}`：研究库和概览所需的稳定产品状态。
- `GET /company-research-runs/{id}/workbench`：一次返回经验证的概览、商业、预测、价值、证据索引和备忘录引用；不返回凭证、原始异常或未授权字节。
- `GET /company-research-runs/{id}/evidence` 和 `GET /evidence/{id}/reader`：来源清单、谱系、精确定位和受许可原文阅读数据。
- `POST /company-research-runs/{id}/critical-input-decisions`：追加用户确认、编辑、Unknown 或缺口接受记录。
- `POST /company-research-runs/{id}/recalculate`：从冻结且已确认的输入生成新的模型候选，不覆盖旧产物。
- `POST /company-research-runs/{id}/publish`：仅在可回答性与关键输入门槛满足时协调现有 publication service。
- `GET /research-archives/...`：继续使用现有只读历史、详情、边界和差异接口；任何不可验证谱系均 fail-closed。

所有响应使用 closed schema。浏览器必须拒绝未知字段、错误身份元组、缺失来源引用和与冻结 basis 不一致的内容。

## 11. 失败处理与恢复

| 情形 | 系统行为 | 用户可见结果 |
| --- | --- | --- |
| 来源不可用 | 仅在等价且合规的替代来源存在时切换，并记录来源变化。 | 显示替代来源；没有替代时创建缺口。 |
| 无授权、留存不支持或 locator 不完整 | 不入 source manifest/正式证据。 | 标记为未证实线索，不能用于模型。 |
| 来源冲突 | 并列保留口径、期间和数值，不由 AI 选择。 | 引导用户选择适用口径、保留冲突或接受缺口。 |
| 解析失败 | 保留安全的来源失败记录，不产生看似有效摘录。 | 显示“无法解析”与可恢复建议。 |
| AI 输出不合约 | 以结构化 schema 与冻结输入交叉验证；只对 provider/格式错误有限重试。 | 重试耗尽后保留已完成阶段；内容成为假设或 Unknown。 |
| 运行中断 | 阶段产物、幂等键和 lease 持久化。 | 从最后一个认证阶段恢复；取消后仍可阅读已完成产物。 |
| 关键基线缺失 | 允许完成业务分析和研究计划，不允许生成伪精确估值。 | `needs_input` 或 `not_answerable`，并列出解决条件。 |
| 历史谱系损坏 | 不读取 current head 补全。 | 返回安全错误并隐藏不可信细节。 |

## 12. 验证与验收

### 12.1 单元与领域测试

- 输入类型的闭合枚举、必填字段、单位/期间和父输入完整性。
- 来源事实不可变；AI/用户假设不能携带伪造来源；Unknown 不得隐式为零。
- source manifest 的授权、时间、哈希、locator 和留存策略 fail-closed。
- 派生计算可重算；关键输入选择由依赖关系稳定重现。
- 关键基线或确切市场引用缺失时，估值和发布门禁失败。
- 历史回放只使用冻结 parent refs；后续数据不能改变旧版本。

### 12.2 编排和 API 集成测试

- 正常阶段推进、等价来源切换、全部来源失败和权限不足。
- AI 格式错误、有限重试、重试耗尽、非法引用和不允许静默补全。
- 中断、lease 过期、幂等重放、恢复和取消。
- 冲突来源并列、关键输入确认/修改/Unknown/接受缺口，以及发布前门禁。
- 精确原文阅读接口的身份、权限、定位、上下文与谱系验证。

### 12.3 浏览器端到端测试

必须通过真实浏览器、真实 API、隔离数据库和受控 worker 完成：

```text
输入公司
→ 启动研究
→ 读取阶段、缺口与关键发现
→ 从结果打开证据中心和冻结原文定位
→ 审阅商业模式、预测与价值边界
→ 确认/修改关键输入或标记 Unknown
→ 保存唯一冻结版本
→ 回放该版本并验证导出哈希
```

E2E 不得通过浏览器外直接调用模型构建、确认或发布服务来伪造成功。

### 12.4 双案例验收

- **可回答案例（CATL）：** 使用真实、授权、可冻结的一手资料；形成完整商业/财务基线、三情景、带敏感性的价值区间、反证、证据阅读、确认、保存、回放和导出。
- **不可回答案例（Alphabet）：** 保留真实来源与多证券边界；在关键缺口未关闭时维持 `not_answerable`，不产生方向、目标价值或回报区间；仍输出有用的商业分析、反证、缺口与验证计划，并可保存和回放。

这两个案例分别证明系统能在证据充分时回答，也能在证据不足时拒绝回答。

## 13. 分阶段演进

### 阶段 1：一键公司研究主线

交付 `CompanyResearchRun`、稳定运行状态、7 页工作台、自动初稿、结果优先概览、证据中心、精确阅读器、关键输入确认、保存、回放与导出。以一个可回答案例和一个不可回答案例完成真实 E2E 验收。

### 阶段 2：可控修改与增量更新

允许编辑收入增速、利润率、资本开支、折现率和终值等假设；每次编辑创建新的可审计计算候选。新财报和公告产生 `UpdateCandidate`，展示事实、模型、价值和判断变化的原因，用户确认后再形成后继版本。

### 阶段 3：稳定后再扩展

只有阶段 1 和 2 的证据、历史、可回答性与 E2E 门槛长期稳定后，才评估公司横向比较、基金/ETF 持仓映射和事件影响研究。任何扩展都不能改变单公司入口、证据准入或“不确定即保留不确定”的核心规则。

## 14. 完成定义

本设计完成的标志不是生成更多页面或更长报告，而是用户可以稳定地完成以下动作：选择公司、阅读其如何赚钱、看到关键变量如何进入预测、检查价值判断依赖的精确资料、识别反证和未知、处理真正关键的输入、并保存一个后来仍能忠实回放的研究版本。

任何不能满足上述证据、时间、授权、可回答性和回放要求的输出，都不是完成的公司研究，必须以线索、缺口或失败状态呈现。
