# 事件主体研究流程设计

## 目标

将正式 Case 工作台改为事件主体的连续研究界面。用户进入任意 `/events/:caseId` 页面后，首先知道正在研究哪个事件，其次知道该事件进行到哪，最后只看到当前需要完成的一项动作。

## 已确认设计

### 事件是一级对象

- 页头左上显示“当前事件研究”和事件标题，点击后展开事件切换器。
- 切换器读取 `listEventResearch()` 的真实事件列表，显示事件标题、公司或代码、研究状态、下一人工动作和更新时间。
- 选择其他事件后保留当前工作区后缀。例如从一个事件的 `/evidence` 切换到另一个事件时仍进入 `/evidence`。
- “返回研究调度”和“新建事件研究”是切换器中的辅助入口，不再使用突兀的原生 select。
- 页面标题、范围、证据、结论、运行和待办始终属于当前事件，不使用“切换 ResearchCase”等系统内部措辞。

### 研究进展属于当前事件

事件标题下显示六个研究阶段：资料接入、定义研究、执行补证、审核证据、形成结论、持续跟踪。阶段由 `EventWorkbench.lifecycle.status`、`conclusion.state`、`progress.pending` 和 `nextAction.kind` 推导，不伪造后端状态。

状态映射：

- `extracting`：资料接入
- `awaiting_scope` 或 `edit_factors`：定义研究
- `researching`、`continuing`：执行补证
- `awaiting_key_review`、`review_intake`、`review_evidence`：审核证据
- `draft_ready`、`review_conclusion`：形成结论
- `published`：持续跟踪
- `exhausted`：停在形成结论，并明确显示范围已穷尽

阶段条表达“当前事件进展”，现有五个一级导航继续表达“工作区”，两者不可混为一谈。

### 当前唯一任务

- 结论概览右侧保留一个主任务入口，标题直接使用 `nextAction.label`。
- 任务卡明确展示：谁需要做、为什么现在需要、进入后要完成什么、完成后系统会做什么。
- 主按钮根据 `nextAction.kind` 进入已有真实页面：原文核验、证据审核、结论审核、范围编辑、结论历史或监测运行。
- 系统运行中或已发布且无人工待办时，任务卡明确写“现在无需操作”，按钮仅用于查看运行或已发布结论，不制造人工动作。
- 用户完成具体页面中的真实提交后，继续使用后端返回的新生命周期与既有路由，不在前端用定时器伪造状态推进。

## 响应式与可访问性

- 事件切换器使用按钮、弹出列表和可访问名称，支持键盘焦点与 Escape 关闭。
- 窄屏下弹层占可用宽度，事件标题可换行，状态与下一动作不被横向裁切。
- 原有 Case 工作区一级、二级导航和全部深链接保持可访问。
- 加载失败时不展示其他事件的替代数据；事件列表读取失败不影响当前事件内容。

## 验收

1. 页头不再出现“查看 Case 状态”或原生“切换 ResearchCase”。
2. 用户能在页头展开真实事件列表，并切换到另一个事件的同一工作区。
3. 切换后标题、状态、阶段、下一动作全部来自新事件。
4. 六阶段进展和五个工作区语义分离。
5. 结论页明确回答“现在谁要做什么、为什么、完成后发生什么”。
6. 现有事件路由、证据审核、结论发布、监控和窄屏导航测试保持通过。
