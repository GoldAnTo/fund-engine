# 公司研究真实调用闭环

用户已确认沿用七页原型，并于 2026-09-09 授权“按照你的建议走完一套流程先”。本轮在第一阶段分支上继续实施，不另建产品入口。

## 本轮完成条件

选择已有完整身份适配的 Alphabet，以已治理的 2026-08-25 历史截止日期运行一次真实研究：重新获取公开披露原件，核验其与既有数字证据相同，冻结本次送入模型的文本；真实 LLM 使用关注问题与引用材料产生商业分析、经营驱动、候选假设、反证和研究报告；初稿无需等待全部证据审核即可阅读；正式数字模型仍由确定性引擎运行；审核与确认后保存精确绑定初稿和原文的版本，刷新、回放及导出一致。

这是一份历史资料研究，不声称包含全部最新披露。固定治理源改变或无法获取时明确失败，不退回样例冒充真实采集。没有已确认的预测输入时，报告解释缺口，不凭空形成估值。

## 设计

1. 复用现有公司初始化、preparation、worker、证据、模型与 publication。原始 scope/basis/request hash 不改变。本次 HTTP 获取另有 source bundle 和执行收据，绑定 URL、抓取时间、发布与可用时间、原件及文本哈希、实际输入片段。
2. 新增独立不可变研究初稿记录，绑定 preparation、project、原 request hash、focus、source bundle、prompt 版本、AIRun 与响应。避免把自然语言初稿混入现有精确计算产物协议。
3. 源准备阶段在事务外获取原件并调用 LLM；完成后经过原有 claim fencing 原子保存证据与初稿。失败、超时、过期写入均保留实际调用审计，但不发布无效初稿。
4. 模型输出采用严格 JSON：商业分析、经营驱动、候选假设、反证、待核验问题、报告章节。引用只能指向提供的 excerpt，摘录必须精确匹配。原文视为数据，不接受其中指令。模型不能提供审核身份、确认状态或财务计算结果。
5. 工作台增加初稿投影，沿用七页阅读路径。初稿明确“模型生成、待确认”，展示可追溯引用和资料边界；既有正式模型与估值门槛保持有效。
6. 确认备忘录时绑定初稿 ID/content hash/source bundle hash。冻结与回放验证这组绑定；已有无初稿的历史版本保持兼容。模型调用摘要和 usage 可核验，密钥、认证 URL 与上游异常正文不进入日志或报告。

## 实现取舍

采用每次重新核验固定已治理披露的方案，能够在当前严格治理链上完成真实获取和模型阅读。暂不把任意来源目录、任意公司适配和可自由修改的预测假设混入这个验收切片。后续再推广来源与公司范围。

## 验证

- 离线测试：HTTP 不符/超限/失败、原文哈希、引用越界、错误 JSON、focus 绑定、模型异常与过期 claim、未经审核初稿可读、既有模型门槛、冻结/回放篡改保护。
- 真实运行：使用现有本地模型配置，仅发送公开披露与研究问题；保存模型名称、真实 usage、原件/输入/响应哈希、项目与冻结版本 ID。
- 浏览器：创建新研究 → 初稿可读 → 查看依据 → 处理已有数字证据 → 确认并保存 → 刷新回放 → 导出。
