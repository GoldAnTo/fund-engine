# 公司研究真实调用闭环

用户已确认沿用七页原型，并于 2026-09-09 授权“按照你的建议走完一套流程先”。本轮在第一阶段分支上继续实施，不另建产品入口。

## 本轮完成条件

选择已有完整身份适配的 Alphabet，以已治理的 2026-08-25 历史截止日期运行一次真实研究：重新获取公开披露原件，核验其与既有数字证据相同，冻结本次送入模型的文本；真实 LLM 使用关注问题与引用材料产生商业分析、经营驱动、候选假设、反证和研究报告；初稿无需等待全部证据审核即可阅读；正式数字模型仍由确定性引擎运行；审核与确认后保存精确绑定初稿和原文的版本，刷新、回放及导出一致。

这是一份历史资料研究，不声称包含全部最新披露。固定治理源改变或无法获取时明确失败，不退回样例冒充真实采集。没有已确认的预测输入时，报告解释缺口，不凭空形成估值。

## 设计

1. 复用现有公司初始化、preparation、worker、证据、模型与 publication。原始 scope/basis/request hash 不改变。本次 HTTP 获取另有 source bundle 和执行收据，绑定 URL、抓取时间、发布与可用时间、原件及文本哈希、实际输入片段。
2. 新增独立不可变研究初稿记录，绑定 preparation、project、原 request hash、focus、source bundle、prompt 版本、AIRun 与响应。避免把自然语言初稿混入现有精确计算产物协议。
3. 源准备阶段在事务外获取原件并调用 LLM；完成后经过原有 claim fencing 原子保存证据与初稿。失败、超时、过期写入均保留实际调用审计，但不发布无效初稿。
4. 模型输出采用严格 JSON：商业分析、经营驱动、候选假设、反证、待核验问题、报告章节。引用只能指向提供的 excerpt，摘录必须精确匹配。原文视为数据，不接受其中指令。模型不能提供审核身份、确认状态或财务计算结果。
5. 工作台增加初稿投影，沿用七页阅读路径。初稿明确“模型生成、待确认”，展示可追溯引用和资料边界；既有正式模型与估值门槛保持有效。
6. 确认备忘录时绑定初稿 ID/content hash/source bundle hash。冻结与回放验证这组绑定；已有无初稿的历史版本保持兼容。模型调用摘要和 usage 可核验，密钥、认证 URL 与上游异常正文不进入日志或报告。

## 实现取舍

采用每次重新核验固定已治理披露的方案，能够在当前严格治理链上完成真实获取和模型阅读。暂不把任意来源目录、任意公司适配和可自由修改的预测假设混入这个验收切片。后续再推广来源与公司范围。

## 验证

- 离线测试：HTTP 不符/超限/失败、原文哈希、引用越界、错误 JSON、focus 绑定、模型异常与过期 claim、未经审核初稿可读、既有模型门槛、冻结/回放篡改保护。
- 真实运行：使用现有本地模型配置，仅发送公开披露与研究问题；保存模型名称、真实 usage、原件/输入/响应哈希、项目与冻结版本 ID。
- 浏览器：创建新研究 → 初稿可读 → 查看依据 → 处理已有数字证据 → 确认并保存 → 刷新回放 → 导出。

## 已确认的运行条件

现有后端模型配置的 MiniMax-M2.7-highspeed 已真实连接成功，返回 JSON 正常；连接验证为 32 input + 47 output tokens，非 mock。此连接检查不等于研究链验收。

## 用户要求替代 SEC 直连后的接入方式

用户继续要求用其他方式解决下载问题。本轮采用 Alphabet 官网财报组件实际提供的 2025 年 10-K PDF，地址为 `https://s206.q4cdn.com/479360582/files/doc_financials/2025/q4/GOOG-10-K-2025.pdf`。下载验证为 940068 bytes、99 页、SHA256 `9953e8d2e70b18c5bf0af3b2b2a1e96de0555f51cbb39a625497b434e19fb43a`。它与 SEC HTML 不是同一份原始字节。

使用来源收据 v2：文档身份、引用及原件哈希记录实际 PDF；`governed_source` 保留已有数字证据引用的身份，`fact_verifications` 保存逐项对应报表的精确摘录和页码。五项年度收入核对 PDF 第 34 页的单位、年度列及完整行，资本支出核对第 53 页现金流表的购置支出及流出符号。原 Q4 财报仍独立抓取及核验。每条核验摘录同时放入模型可见片段。

这一映射只支持已逐项核验、固定哈希的两份官方文件；不能把任意 PDF 声称为已有证据的副本。旧 v1 收据继续可回放，原有证据、范围和确定性模型协议不变。启用 `COMPANY_RESEARCH_SOURCE_PROFILE=official_ir` 后不向 SEC 发出抓取请求，也不需要联系邮箱。

## 真实模型输出后的引用接口调整

真实响应证明，让模型逐字抄写 PDF 原文不够稳定：一次完整响应中 29 条引用只有 4 条逐字匹配，16 条改动了空白，另外 9 条在空白归一后仍不能与输入连续片段对应；还出现正文年份、比例和金额以及超长引用。维持原有拒绝规则，不以放宽校验完成验收。

改用 provider 引用选择接口：从本次冻结的片段确定性切出连续原文，为每段分配短引用 ID；模型选择 ID，系统回填精确原文及其文档身份，再通过原有引用、事实键和数值校验。候选目录、新 schema 和 prompt 均进入输入哈希。完整保存结构继续使用已解析的原文引用，旧版本回放不依赖新 provider schema。

Prompt v2 显式要求正文不含年份、季度编号、金额、比例或中文数量表达；披露数字只通过受认可事实键展示。未知引用 ID、混合引用字段、跨文档错误的事实键绑定仍拒绝。

## 有界的校验反馈修正

真实 v2 请求已能稳定选择精确原文 ID，但三次响应仍分别存在正文年份或比例、单项引用超过四条、年度事实只引用季度文档的问题。对完全相同的输入重复请求不能提供具体改正方向。

Prompt v3 在单次生成中最多调用模型两次。首次返回可解析 JSON 但未通过研究输出校验时，向同一模型提供它的原始响应和结构化的字段错误，要求重新提交完整 JSON。反馈包含错误路径、约束和合法来源对应关系，不使用外部资料，也不回显上游异常或认证信息。传输、配置或输入失败不触发内容修正；第二次仍无效时拒绝保存。两次调用共用总时间预算。

最终输出继续通过完整原有校验，程序不会删改正文、截断引用、补造事实或把失败响应当成报告。调用审计记录每次请求和响应哈希、结果及校验反馈，并保存真实用量；双次调用使用有版本标识的输入哈希链。失败收据同样保留已发生的调用，既有单次调用与历史初稿继续可回放。
