# 独立公司与行业投资研究产品：三屏高保真原型设计

日期：2026-08-20

状态：待用户审阅

交付类型：独立、可抛弃、可点击的高保真原型

## 1. 产品定义

这是一个从股票、公司或行业入口开始的投资研究产品。它帮助严肃个人投资者和投资经理建立、验证并持续更新对一家公司的投资判断，而不是自动生成一份公司长报告。

核心路径只有三步：

```text
搜索股票 / 公司 / 行业
→ 确认研究对象、问题与期限
→ 进入公司研究工作台，维护判断、分歧、估值与验证
```

研究深度不由报告字数、来源数量或运行时间证明。只有能够识别关键变量，并把变量传导到收入、利润、自由现金流、每股价值、当前价格要求和证伪条件，才算形成了有投资意义的研究。

## 2. 与旧项目的强制隔离

新原型建立在独立目录和独立页面壳中，不继承旧 Fund Engine 的信息架构、导航或用户可见术语。

以下概念不得出现在新产品的一级界面：

- ResearchCase、Case、Event Research、ResearchRun；
- 证据图谱、运行监控、Worker、固定自动研究阶段；
- “自动研究完成”、综合研究评分、AI 置信度；
- 旧式“结论、证据、市场、监控、图谱”标签组；
- 默认长报告、新闻流和来源数量指标。

底层未来可以复用实体识别、来源追溯、财务数据和版本记录能力，但这些能力不能决定新产品的页面结构。

## 3. 用户与成功标准

### 3.1 主要用户

- 严肃个人投资者：需要系统研究一家公司，但不应被复杂机构流程阻挡。
- 投资经理和研究员：需要把市场预期、我方分歧、经营预测、估值和反证放在同一个决策界面。

两类用户共用同一研究内核。机构用户后续可以增加负责人、复核、组合语境和权限，但第一版不做仓位建议或组合优化。

### 3.2 原型成功标准

首次用户应能在 5 秒内知道可以输入什么以及如何开始。进入工作台后，用户应能在 2 分钟内回答：

1. 研究的是哪家公司和哪只证券？
2. 当前研究问题和判断期限是什么？
3. 公司靠什么赚钱，最关键的 2–4 个变量是什么？
4. 市场一致预期与当前价格分别要求什么？
5. 我方在哪些变量上存在分歧？
6. 最强反证、最大未知和下一验证事件是什么？
7. 这些分歧如何影响收入、利润、自由现金流和估值？

## 4. 已考虑的产品路径

### 路径 A：搜索后自动生成公司报告

优点是演示效果直接。缺点是把研究等同于内容生成，用户无法知道关键因素为何重要，也无法区分事实、解释和幻觉。否决。

### 路径 B：聊天式研究助手

优点是入口简单。缺点是用户需要知道该问什么，判断、反证、预测和版本无法稳定保留，容易退化成问答工具。否决为主路径，可作为未来辅助交互。

### 路径 C：主体确认 → 研究框定 → 判断工作台

这是推荐路径。它先消除公司和证券识别错误，再用极少输入明确问题、期限与反证，最后进入结构化工作台。它既适合首次用户，也能容纳机构级深度。

## 5. 三屏信息架构

## 5.1 第一屏：搜索与开始

### 唯一职责

回答“我研究的是谁”，不提供投资结论。

### 页面结构

1. 极简顶部：产品名称、“我的研究”、账户入口。
2. 中央主标题：从一家公司开始，理解它如何赚钱、行业如何变化、当前价格要求什么成立。
3. 主搜索框：支持股票代码、公司名、别名、行业和业务关键词。
4. 三个静态输入示例，不使用“热门”标签。
5. 输入后按“股票、公司、行业”分组显示结果。
6. 返回用户可在下方看到最多三条已有研究，并选择继续。

### 搜索结果必须显示

- 实体类型和匹配方式；
- 公司法定名称、股票代码、交易所、股权类别、币种；
- 公司与证券的对应关系；
- 核心业务一句话；
- 数据覆盖与截止时间；
- 数据缺口，例如缺少一致预期或分部数据；
- 是否已有研究，避免重复建立互相冲突的判断。

### 行业入口

行业搜索不直接生成宏观行业报告。用户先选择一家代表公司进入研究，行业关键词作为上下文带入。正式行业工作台不在本原型范围内。

### 不默认展示

涨跌幅、K 线、成交额、新闻、情绪、热门榜、相似股票、AI 投资摘要、估值高低、目标价和推荐。

### 关键异常

- 多个同名主体：要求选择市场和证券，不默认市值最大者。
- 非上市公司：允许确认公司，但明确不能进行价格隐含预期分析。
- 无结果：区分实体不存在、数据未覆盖、权限不足和服务不可用。

## 5.2 第二屏：建立研究

### 唯一职责

回答“我要验证什么，什么会推翻它”。这不是创建项目表单，也不是配置自动研究任务。

### 页面结构

1. 已确认对象：公司、证券、交易所、股权类别、业务和行业上下文。
2. 核心问题：提供一个默认问题、两个问题模板和自定义输入。
3. 研究期限：1–2 年、3–5 年（默认）、5 年以上。
4. 可选折叠区“我已经有一些想法”：初步判断和最担心的问题。
5. 右侧研究预览：只显示即将回答的四个问题和一个默认反方问题，不预览报告目录。
6. 主操作“建立研究”，次级操作“使用默认问题直接开始”。

### 默认研究问题

> 以 3–5 年视角，这家公司靠什么创造价值，当前价格要求哪些假设成立？

### 最少必要输入

- 必须：确认无误的公司和证券主体。
- 有默认值：研究问题、研究期限。
- 自动推断：行业上下文、币种、财年和主要结果变量候选。
- 可选：用户初步判断、最担心的问题。

用户初步判断必须标记为“你的假设”，不能混入公开事实或系统解释。

系统根据默认研究问题提出一个“什么情况会推翻当前假设”的候选反方问题，并标记为“系统建议，待确认”。个人用户可以不编辑它直接开始，避免在信息不足时被迫编造证伪条件。候选反方只有在后续绑定观察指标、期间、财务影响和验证事件，并由用户确认后，才进入正式判断版本。

### 不询问

投资金额、仓位、买入价格、目标价、预期收益率、投资风格标签、报告页数、数据源、指标清单、估值模型、情景概率和新闻数量。

### 建立后的状态

点击后立即进入工作台，不显示“正在生成完整报告”。工作台按真实可用性渐进呈现：

```text
已确认公司与证券
正在整理业务与分部
正在建立经营基线
正在识别关键变量和价格问题
```

后台任务只能写“本轮处理结束”，不能写“研究完成”。

## 5.3 第三屏：公司研究工作台

### 唯一职责

回答“现有事实允许我判断到哪一步，以及下一步应验证什么”。工作台不是报告阅读器、新闻终端或运行控制台。

### 顶部上下文

- 公司、具体证券、交易所和股权类别；
- 当前价格与时间戳；
- 研究问题和期限；
- 资料截止时间；
- 产物类型：机器工作摘要、研究员暂定判断或人工确认版本；
- 是否存在过时数据或未经核对的核心来源。

### 首屏阅读顺序

```text
当前允许得出的判断 | 最大反证 | 当前价格问题
──────────────────────────────────
2–4 个关键因素：我方、市场、证据状态、财务影响
──────────────────────────────────
公司如何赚钱 | 行业供需与竞争位置
──────────────────────────────────
预测与估值 | 最大未知 | 下一验证事件
```

### 当前判断区

最多两句话。证据未齐全时使用“当前已知”“尚不可判断”或“冲突未决”，不强行生成结论。最大反证必须与判断并列，不能放入风险页末尾。

### 关键因素

首屏最多四项。每项显示：

- 因素名称与为什么关键；
- 当前值和趋势；
- 历史实际、公司指引、市场一致预期、价格隐含值和我方假设；
- 对收入、利润、自由现金流或估值的传导；
- 当前证据状态、数据新鲜度；
- 最强反证、下一验证事件和证伪阈值。

点击因素后行内展开固定路径：

```text
机制假设
→ 观察事实
→ 支持证据 / 反证 / 替代解释
→ 预测指标和验证日期
→ 财务与估值影响
→ 对当前判断的影响
```

### 公司与行业

首先展示公司如何赚钱：业务分部、收入、利润、资本开支和现金流。行业内容只保留与关键因素有关的供需、竞争、价值链位置和利润池变化，不做百科全书式行业介绍。

### 市场预期必须分层

- Consensus：卖方一致预期，包含覆盖数、区间、修订方向和时间戳。
- Implied：由当前价格反推的一组等价经营假设，展示方法和敏感性，不宣称唯一答案。
- Narrative：当前主流多头、空头叙事，明确区分有数据支持和重复传播的观点。

三层不得合并成一个“市场预期”。

### 预测与估值

- 先展示经营假设如何传导到收入、利润、自由现金流和稀释后每股价值。
- 展示估值区间与敏感性，不默认显示精确单点目标价。
- 所有数字标明定义、单位、期间、币种、来源、as-of 和类型。
- Bull、Base、Bear 如使用，必须由不同机制驱动，不能机械上下浮动，也不显示未经校准的概率。

### 统一数据类型

任何数字或陈述必须属于以下类型之一：

- Actual：历史实际；
- Guidance：公司指引；
- Consensus：一致预期；
- Implied：价格隐含；
- House：我方预测；
- Scenario：情景假设；
- Estimate：未经验证估算。

缺失值显示“缺失”或“未覆盖”，不得显示为零或由 AI 静默补齐。

### 新闻与材料

新闻不是一级对象。只有当材料能够关联某个关键因素，并说明支持、反驳、背景或未知时，才进入工作台。没有因果识别设计时，只能写“同期观察”或“可能解释之一”，不能写“新闻导致股价上涨/下跌”。

### 唯一下一动作

工作台首屏只提供一个主动作，例如补齐经营基线、核验反面证据、更新估值或提交人工判断。其他动作下沉，避免十几个等权按钮。

## 6. 原型交互与状态

### 6.1 主路径

1. 在搜索页输入或选择 Alphabet/GOOGL 示例。
2. 在结果中区分 Alphabet 公司、GOOGL Class A 和 GOOG Class C。
3. 选择 GOOGL 后进入建立研究页。
4. 接受默认问题和期限，或填写一条用户假设。
5. 点击“建立研究”进入部分可用的公司工作台。
6. 点击关键因素，行内展开机制、证据、反证和财务传导。
7. 展开“当前价格要求”，查看反向估值假设和敏感性。

### 6.2 状态必须正交

- 数据处理：未开始、读取中、部分可用、读取失败。
- 证据：AI 提取未核对、来源已核对、人工确认、已排除、已过时。
- 研究判断：尚不可判断、证据不足、冲突未决、暂定判断、人工确认、需要更新。
- 预测：假设草案、已冻结、未到验证期、已有实际、已复核。

不能用一个绿色“完成”覆盖这些状态。

### 6.3 原型数据边界

使用明确标记的模拟公司数据，目的只为评估信息结构。原型不连接真实行情、财务数据、新闻或 AI 服务，不产生投资建议。

## 7. 视觉方向

### 7.1 场景句

一位认真但不希望操作机构级复杂系统的投资者，在白天的 27 英寸显示器上开始一项长期公司研究，需要安静、清楚地知道下一步，而不是被行情和资讯催促。

### 7.2 视觉策略

- 浅色、克制、中性偏暖的阅读表面；使用一个低饱和蓝紫强调当前步骤和主要动作。
- 搜索页无左侧导航，以中心搜索和清晰示例建立入口。
- 建立研究页采用单页双栏结构，不使用冗长向导或项目配置表。
- 工作台采用非对称阅读布局，判断、反证和价格问题优先，因素与模型按需展开。
- 使用系统中文字体、清晰数字字形和固定应用字号。
- 不使用满屏同尺寸卡片、玻璃拟态、渐变文字、大目标价、红绿买卖灯、知识图谱和行情大图。

### 7.3 高保真原型变体

三屏主流程固定。只在第三屏提供三个可切换的结构变体：

- A，判断优先：判断、反证、价格问题在首行，关键因素为主体。推荐默认。
- B，模型优先：经营驱动树和我方/市场差异先于判断，适合建模型研究员。
- C，备忘录优先：按问题、分歧、估值、证伪和下一动作线性阅读，适合 PM 复核。

变体通过 URL 参数和底部原型切换器切换。搜索与建立研究页面保持一致，避免把流程变量与工作台布局变量混在一起。

## 8. 响应式与可访问性

- 桌面基准：1600 × 1000；同时检查小型笔记本、390px 移动端。
- 移动端阅读顺序：主体与时间 → 当前判断 → 最大反证 → 价格问题 → 关键因素 → 公司与行业 → 预测估值 → 未知与下一验证。
- 核心功能不依赖悬停。因素详情使用行内展开，证据详情使用侧栏或移动端全屏层。
- 键盘可完成搜索、选择主体、建立研究、展开因素和切换工作台变体。
- 状态同时使用文字和形状，不只依靠颜色。
- 以 WCAG 2.2 AA 为基础，交互目标至少 44px。

## 9. 不在本原型范围

- 真实数据接入、账户、权限和持久化；
- 自动研究编排、后台 Agent 状态和运行监控；
- 正式行业工作台；
- 基金映射、持仓穿透和组合优化；
- 投资建议、仓位建议、交易下单；
- 完整三表模型编辑器；
- 报告导出、投委会审批和多人协作。

## 10. 验收与一票否决

### 必须通过

- 去掉 Logo、颜色和产品名后，用户仍自然描述为“先确认主体，再定义问题，再维护公司判断”。
- 首屏删除报告字数、来源数量和运行耗时后，研究价值仍然成立。
- 没有证据时界面主动变短并停止，不生成长文填满页面。
- 任一预测和估值数字都能定位到定义、期间、单位、as-of、假设和验证条件。
- 支持材料再多，也不能自动覆盖一条高质量反证。
- 用户能在两步内从任一关键判断回到对应事实和来源边界。

### 一票否决

- 用户可见核心对象仍是 Case、Event 或 Run；
- 搜索页出现新闻、行情门户或 AI 买卖摘要；
- 建立研究页变成旧 Case 字段改名或自动研究配置；
- 工作台默认展示长报告、知识图谱、新闻流或运行进度；
- “自动研究完成”、AI 置信度、综合评分、买卖评级或单点目标价；
- 一致预期与价格隐含预期被合并；
- 最大反证、数据缺口和下一验证被折叠隐藏；
- 未识别因果关系却把新闻写成股价原因。

## 11. 原型最终交付

- 独立目录中的 HTML、CSS 和 JavaScript；
- 一个命令启动的本地静态服务；
- 三屏可点击主路径；
- 工作台 A/B/C 三个结构变体；
- 1600 × 1000 主截图、390px 移动端截图；
- README，明确原型问题、模拟数据边界和访问方式。
