# 动态投资承保系统设计

日期：2026-08-21

状态：视觉设计已确认，待用户书面审阅

首个纵向案例：动力电池行业 → 宁德时代 → 300750.SZ

第二复用案例：Alphabet → 搜索广告 / Cloud / AI 投入 → GOOGL / GOOG

## 1. 设计结论

本产品不是自动研报、新闻分析器、单点估值工具或交易系统。它是一套动态投资承保系统：在明确的投资期限和回报要求下，持续判断当前价格是否值得承担一组未来经营结果，并保留每次判断变化的完整依据。

推荐架构为：

```text
C 是产品架构：动态投资承保系统
A 是用户界面：三时钟决策台
B 是可信底座：事实、信念、决策和校准账本
```

核心主链：

```text
事实
→ 机制与信念
→ 经营预测
→ 价格隐含预期面与价值分布
→ 可回答性与承保闸门
→ 允许动作
→ 不可变版本与后续校准
```

系统不以材料数量、报告长度、AI 置信度或目标价证明研究深度。只有关键经营机制能够回到来源、映射到财务、约束估值并形成可证伪动作条件时，研究才进入正式决策层。

## 2. 产品宪法

以下规则为一票否决项，后续功能不得绕过：

1. 证据、机制或估值可识别性不足时，系统必须输出“当前不可判断”。
2. 不输出 AI 综合评分、确定性买卖评级或单点目标价。
3. 新闻和事件不能直接改变投资判断，必须经过增量信息、机制、预测和价值传导。
4. 事实、判断、证伪条件、预测、估值和动作只能追加新版本，不能静默覆盖。
5. 系统输出允许动作和成立条件，不自动交易，也不在第一阶段给出仓位比例。
6. Industry、Company 和 Security 是不同研究对象，不得以股票代码替代公司或以行业叙事替代证券估值。
7. 行业变化只能触发公司复核，不能自动改写公司预测或承保结论。
8. 缺失、冲突、过期或无授权数据必须显式显示，AI 不得静默补齐。

## 3. 用户、任务与边界

### 3.1 用户

- 严肃个人投资者：没有真实持仓也能判断一家公司是否值得进入观察或建立初始仓位。
- 投资经理和研究员：需要可追溯、可复核、可比较和可校准的行业与公司判断底座。

两类用户共享研究内核。组合约束、真实持仓、仓位比例、交易执行、权限和多人审批不在第一阶段。

### 3.2 无持仓决策语言

第一阶段使用：

- `observe`：进入观察；
- `wait_for_validation`：证据缺失或冲突但可合理解决，当前冻结行动；
- `eligible_for_probe_entry`：允许试探建仓；
- `eligible_for_staged_entry`：允许分步建仓；
- `do_not_enter`：核心逻辑失效、违反可投资边界，或无法在授权的成本与时间内形成可回答判断。

不得使用“持有、加仓、减仓、止损”描述不存在的真实仓位。

### 3.3 明确不做

- 纯短线价格预测、技术交易与新闻情绪交易；
- 自动仓位和真实下单；
- 全行业与全市场一次性覆盖；
- 强制股价因果归因；
- 一次性长报告、AI 买卖摘要和内容数量评分；
- 未校准的精确情景概率；
- 把 PE、PB 或历史低位直接定义为便宜。

## 4. 三时钟投资边界

### 4.1 经营时钟 BusinessClock

默认三至五年，回答公司的价值创造机制、竞争位置、资本回报和长期现金流是否成立。

### 4.2 预期时钟 ExpectationClock

默认未来二至六个季度，回答我方与市场分歧何时、由哪些指标和事件验证。

### 4.3 价格时钟 PriceClock

覆盖当前至数月，回答当前价格位于哪个经营情景、是否提供合适进入条件。它不单独产生短线方向预测，也不能改写经营时钟上的逻辑。

## 5. 一级研究对象

### 5.1 Industry

行业是可独立研究、持续版本化的经济系统，而不是公司页面里的背景章节。正式行业研究包含：

- 研究边界、地域、客户和替代品；
- 需求单位、驱动、上限、周期和证伪条件；
- 名义产能、有效产能、良率、认证、投放时滞和退出成本；
- 定价机制、议价权、长协、成本传导与补贴；
- 成本曲线、边际供给者、资本强度和现金回报；
- 竞争者份额、扩产、降价、退出和客户多元化行为；
- 技术与监管如何改变需求、供给、成本、准入或利润分配；
- 行业周期状态与产业链利润池迁移。

行业研究沉淀四类资产：

1. IndustryMechanismMap；
2. IndustryStateVersion；
3. IndustryScenarioSet；
4. CompanyExposureMap。

行业本身不直接产生证券买卖判断。

### 5.2 Company

公司研究从 EarningsEngine 开始，先回答公司到底靠什么赚钱，再讨论关键因素和估值。

每个业务分部必须闭合：

```text
客户是谁
→ 购买什么
→ 如何收费
→ 量、价、份额如何形成收入
→ 成本和费用来自哪里
→ 需要多少资本与营运资金
→ 产生多少利润与自由现金流
→ 贡献多少公司价值
```

“主营业务”至少使用四种不同口径：RevenueCore、ProfitCore、CashCore 和 ValueCore。系统不得以收入最大自动代表价值贡献最大。

公司层还必须覆盖资本配置、股本变化、资产负债表约束、公司治理和行业暴露。

### 5.3 Security

证券层保存具体股权类别、交易所、币种、资本结构、流动性、公司行动、当前价格和时间戳。公司经营价值可以被多个证券引用，但每只证券的价格隐含预期和预期回报必须独立计算。

## 6. 四本账本

### 6.1 RealityLedger

只记录当时可知内容：Observation、SourceStatement、DerivedMetric、来源、双时间、口径、冲突和 Unknown。来源说法不自动成为事实，事实也不自动成为价格驱动。

### 6.2 BeliefLedger

记录 Claim、Mechanism、AlternativeExplanation、Falsifier、逻辑状态和 superseding 版本。每条正式机制必须包含方向、时滞、生效条件、失效条件、量级区间、财务映射和反方解释。

### 6.3 DecisionLedger

记录 InvestmentMandate、ExpectationSurface、House Forecast、ValueDistribution、ResearchDebt、AnswerabilityState、UnderwritingVersion 和 EligibleAction。

### 6.4 CalibrationLedger

当实际结果到来时，把历史预测、时间窗和证伪条件与实际比较，区分：

- 预测误差：量、价、利润率、资本开支、现金流或折现率；
- 行为误差：过早进入、价格锚定、移动证伪线；
- 模型误差：遗漏机制、时滞错误、行业模板失配。

没有历史校准记录时，系统不得展示伪精确概率。

## 7. 经济机制编译器

复用对象不是报告文字或结论，而是受治理的 MechanismPack。

### 7.1 MechanismPack 内容

- 核心变量和公式；
- 指标定义、单位、频率与数据源优先级；
- 财务科目映射；
- 方向、时滞、非线性和阈值；
- 适用范围与失效条件；
- 常见误判、替代解释和证伪规则；
- 可用 ValuationAdapter。

### 7.2 生命周期

```text
候选机制
→ 公司适配
→ 历史校准
→ 研究员确认
→ 正式使用
→ 受到挑战
→ 停用或替换
```

公司可以覆盖行业机制的参数或适用条件，但必须生成新版本并说明原因。行业机制不能自动把结论传播到公司。

### 7.3 典型机制组合

- Alphabet：广告双边市场、Cloud 规模经济、AI 资本强度、平台监管；
- 宁德时代：制造量价成本、产能周期、原材料传导、海外扩张；
- 银行：资产负债表、净息差、信用成本、资本监管；
- 半导体：库存周期、产能利用率、技术节点、资本开支周期。

## 8. 新信息更新协议

任何财报、公告、行业数据、新闻或研究材料依次通过：

1. 身份和双时间锁定；
2. 原始来源冻结；
3. 原子陈述拆分；
4. 事实验证、独立来源与冲突识别；
5. 增量信息测试：是否新、意外、与关键机制相关、尚未计入；
6. 机制更新：支持、反驳、修改条件、候选新机制或无法映射；
7. 预测更新：实际、指引、经营假设和模型结构分别归因；
8. 估值更新：经营、折现率、终值、现金、股本和方法分别归因；
9. 承保门控：可回答性、逻辑、价格、研究债务和风险收益同时检查；
10. 生成不可变版本和 ChangeSet。

没有因果识别时，股价变化只允许标记为 `identified`、`model_inferred` 或 `unexplained`，不得强制精确归因或加总到 100%。

## 9. 盈利引擎与估值适配

估值方法由经济特征决定，不由用户先选一个倍数再填数：

- 多业务集团：SOTP + 分部 DCF；
- 成熟现金流：DCF + FCF Yield；
- 周期制造：中枢利润、成本曲线、资产周期与情景 DCF；
- 银行保险：PB–ROE + 剩余收益；
- 早期增长：单位经济 + 情景 DCF；
- 资源与资产型业务：NAV、重置成本或周期中枢。

每个适配器统一输出：

- 当前价格下的 ExpectationSurface；
- House 经营分布与 ValueDistribution；
- 三至五年预期回报区间；
- 悲观路径与永久损失机制；
- 最敏感的经营变量；
- 方法、来源、期间、币种、as-of 和失效条件。

同一当前价格可由多组经营假设支持。系统必须展示主要可行组合和可识别程度，不得选择其中一组冒充“市场唯一预期”。

## 10. 四维承保决策

系统保持四个维度正交，不计算一个综合分数：

1. ThesisHealth：得到验证、基本完整、受到挑战、核心失效；
2. PriceState：安全边际明显、有吸引力、合理、要求乐观、极度苛刻；
3. ResearchDebt：关键缺失、冲突、陈旧、单一来源、到期未验证和模板失配；
4. PayoffShape：中性回报、悲观损失、永久损失路径和机会成本。

### 10.1 投资授权

即使没有真实持仓，也必须声明：

- 三至五年投资期限；
- 基准币种；
- 最低要求回报或比较基准；
- 可接受的永久损失边界；
- 适用的替代机会集合。

没有 InvestmentMandate，系统可以展示估值，不得宣称是否值得投入资本。

### 10.2 跌后差分

每次显著价格变化必须重新比较：

- `ΔPrice`：证券价格变化；
- `ΔValueDistribution`：更新后价值分布变化；
- `ΔUncertainty`：结果分布是否变宽；
- `ΔThesisHealth`：核心机制仍成立、受挑战或失效。

禁止继续使用旧目标价证明“越跌越便宜”。

### 10.3 无持仓允许动作矩阵

- 逻辑完整 + 安全边际明显 + 研究债务可接受：`eligible_for_staged_entry`；
- 逻辑完整 + 有吸引力：`eligible_for_probe_entry`；
- 逻辑受挑战、关键债务未解决，或 `not_answerable` 但可合理补证：`wait_for_validation`；
- 价格合理但没有足够预期回报：`observe`；
- 核心逻辑失效、违反可投资边界，或不可回答且无法在授权成本与时间内解决：`do_not_enter`。

每个动作同时显示成立条件、阻塞条件、失效条件和下一验证。

## 11. 可回答性闸门与失败关闭

AnswerabilityState 只有：`answerable`、`partially_answerable`、`not_answerable`。

以下任一情况阻止价格结论和进入资格：

- 关键经营基线缺失；
- 核心证据严重冲突且未复核；
- 机制无法从相关性提升到可使用的经济或会计关系；
- 收入、利润、资本投入、现金流和价值无法闭合；
- 价格反推解过于发散，无法形成有意义的 ExpectationSurface；
- 关键来源过期、无权限或无法重现；
- HistoricalBasis 混入当时不可得信息。

失败状态必须提供：阻塞原因、受影响判断、需要补齐的资料或验证、责任动作和下一复核时间。不得以低置信度结论替代失败关闭。

`not_answerable` 是知识状态，不是负面投资结论。可解决的失败关闭映射为 `wait_for_validation`；只有核心逻辑或可投资边界已经失败，或问题无法在 InvestmentMandate 的研究成本与时间边界内解决时，才映射为 `do_not_enter`。两者都不得产生进入资格。

## 12. 版本、ChangeSet 与历史回放

### 12.1 不可变版本链

一次正式更新冻结：

```text
IndustryStateVersion
→ EarningsEngineVersion
→ MechanismVersion
→ ForecastVersion
→ ValuationVersion
→ UnderwritingVersion
```

每个版本绑定 HistoricalBasis，包括数据版本、来源版本、价格时间、模型版本、研究截止和操作者。

### 12.2 ChangeSet

ChangeSet 分开记录：

- 新增、失效或冲突的事实；
- 被加强、削弱、替换或到期的机制；
- Actual、Guidance、Consensus、House 与 Scenario 变化；
- 经营、折现率、现金、股本和模型方法造成的价值变化；
- 价格变化与无法解释部分；
- 不确定性与 ResearchDebt 变化；
- EligibleAction 变化及原因。

### 12.3 不可篡改纪律

- 新判断通过 `supersedes` 连接旧版本，不覆盖旧版本；
- 修改证伪条件必须生成新版本并解释原因；
- 延长验证期限必须留下记录，到期未实现本身作为证据；
- 新价格不能回写旧估值；
- 修正错误通过更正版本完成，不删除历史。

## 13. 用户体验与渐进披露

底层严格，默认界面必须简单。

### 13.1 首页一级入口

- 行业研究；
- 公司 / 证券承保；
- 最近变化；
- 待验证与不可回答事项。

### 13.2 行业工作台

默认显示当前行业状态、最关键的需求 / 供给 / 价格机制、利润池、最大反方、受影响公司和本版本变化。完整来源、指标、机制和历史按需展开。

### 13.3 公司工作台

默认阅读顺序：

```text
InvestmentMandate 与三时钟
→ EarningsEngine：收入、利润、现金与价值核心
→ 当前判断、最大反证和价格问题
→ 3–5 个关键机制
→ ExpectationSurface 与 ValueDistribution
→ 四维承保状态与 EligibleAction
→ 下一验证与 ChangeSet
```

用户默认只看到当前判断、价格要求、最大反证、允许动作、阻塞和下一验证。事实、机制、预测、模型、版本和来源逐层展开。

### 13.4 变化页

变化页优先回答：

1. 哪些事实真的变化；
2. 哪些只是叙事变化；
3. 哪个机制被加强或削弱；
4. 预测为何调整；
5. 价值变化来自什么；
6. 价格与价值谁变化更大；
7. 为什么允许动作改变；
8. 仍有哪些问题无法回答。

## 14. 第一阶段纵向案例

### 14.1 研究路径

```text
InvestmentMandate：3–5 年、无持仓
→ 动力电池 IndustryStateVersion
→ 宁德时代 EarningsEngineVersion
→ 3–5 个关键 Mechanism
→ 300750.SZ ExpectationSurface 与 ValueDistribution
→ UnderwritingVersion
→ 第二时间点 ChangeSet 与 CalibrationRecord
```

### 14.2 动力电池行业最低深度

- EV 与储能需求单位模型；
- 名义产能与有效产能分离；
- 利用率、库存与价格形成机制；
- 材料成本向电芯价格的传导；
- 技术路线和客户认证约束；
- 行业利润池和周期状态；
- 至少一个完整竞争性反方模型。

### 14.3 宁德时代公司最低深度

- 动力电池、储能、海外和其他重要业务分部；
- 各分部收入、利润、现金流、资本占用和价值角色；
- 出货量、ASP、单位成本和利用率；
- 海外盈利、客户结构和竞争位置；
- 资本开支、折旧、营运资本和现金转换；
- 资本配置、净现金、股本和公司行动；
- 每个关键机制连接到财务与估值。

### 14.4 数据策略

第一阶段使用有来源、可冻结的真实历史口径，不伪装成实时系统：

- 定期报告、交易所公告和公司 IR；
- 行业官方或高可信原始资料；
- 明确提供方的财务、行情、行业指标和一致预期；
- 同时保存统计期和首次可获得时间；
- 建立固定 cutoff 的历史基线；
- 后续刷新使用新版本，不覆盖基线。

## 15. 第二复用案例

完成宁德时代纵向切片后，以 Alphabet 验证跨行业复用：

```text
Alphabet
= 广告双边市场
+ Cloud 规模经济
+ AI 资本强度
+ 平台监管
```

允许新增或组合 MechanismPack、MetricDefinition、CompanyOverride 和 ValuationAdapter；不允许新增 Alphabet 专用研究内核、账本类型、版本类型或页面架构。

Alphabet 的 Company 判断可共享给 GOOGL 和 GOOG；Security 价格、股权类别和预期回报独立计算。

## 16. 组件边界

### 16.1 Identity Registry

管理 Industry、Company、Security、业务分部、股权类别、币种和映射。它不持有研究结论。

### 16.2 Evidence & Reality Kernel

冻结来源、双时间、原子陈述、观测、派生指标、冲突和 Unknown。它不产生 EligibleAction。

### 16.3 Industry State Engine

根据正式机制与指标形成 IndustryStateVersion、ScenarioSet 和 CompanyExposureMap。更新只产生复核影响列表。

### 16.4 Earnings Engine

维护公司分部经济性、四类核心、行业暴露、资本配置与 EarningsEngineVersion。

### 16.5 Mechanism Compiler

组合、校准、确认和版本化 MechanismPack，将事实连接到 Driver、Forecast 和 Falsifier。

### 16.6 Forecast & Valuation Engine

区分 Actual、Guidance、Consensus、Implied、House、Scenario 和 Estimate，维护预测、ExpectationSurface、ValueDistribution 与机械归因。

### 16.7 Underwriting Policy

根据 InvestmentMandate、Answerability、ThesisHealth、PriceState、ResearchDebt 和 PayoffShape 生成一个 EligibleAction。它不能下单。

### 16.8 Version & Calibration Kernel

维护 HistoricalBasis、不可变版本、ChangeSet、实际结果和 CalibrationRecord。

各组件通过版本 ID 和明确契约连接；任何组件内部替换不得改变其他组件的领域语义。

## 17. 错误与异常处理

- 数据源失败：保留已冻结版本，标记新鲜度和失败原因，不回退到无来源 AI 填充；
- 实体歧义：要求确认 Company、Security、市场和股权类别；
- 口径变化：创建新的 MetricDefinition 版本并标记不可直接比较；
- 来源冲突：保留冲突双方，不平均后消失；
- 模型不平衡：阻止 ValuationVersion 发布并显示对账差异；
- 价格缺失或停牌：可以维护公司判断，不能形成当前证券承保动作；
- 版本并发：采用基于父版本的乐观并发，冲突生成显式合并任务；
- 机制包失配：回退为候选机制并增加 ResearchDebt，不静默沿用；
- 数据更正：追加更正版本并标记受影响的下游判断。

## 18. 验收标准

### 18.1 研究深度

- 行业与公司各保留 3–5 个真正影响决策的关键机制；
- 每个正式机制能在两步内回到来源、时间、口径和审核状态；
- 每个机制映射到收入、利润、资本投入、现金流或价值；
- 至少存在一个完整反方模型和明确证伪条件；
- 资料不足时页面主动变短并停止。

### 18.2 研究沉淀

- 能重建任一 HistoricalBasis 下当时可见的事实、预测、价格和判断；
- 至少两个版本可比较；
- ChangeSet 能解释事实、机制、预测、价值、研究债务和动作变化；
- 旧结论、证伪条件和模型输入不可静默修改；
- 预测到期后能够生成 CalibrationRecord。

### 18.3 架构复用

- 一个 IndustryStateVersion 可被多家公司版本化引用；
- 公司采用机制包时保留公司特有参数和例外；
- Alphabet 案例不新增专用内核、账本或页面架构；
- 公司经营判断和证券价格判断保持分离。

### 18.4 决策有效

- 能解释当前价格的主要可行假设组合和可识别程度；
- 能比较 House 与 Implied，而不把 Narrative 合并为市场预期；
- 能做 `ΔPrice`、`ΔValueDistribution`、`ΔUncertainty` 和 `ΔThesisHealth` 的跌后差分；
- 能输出一个有成立、阻塞、失效和验证条件的 EligibleAction；
- `not_answerable` 时不输出进入资格。

### 18.5 技术与研究验证

- 历史回放测试防止未来信息泄漏；
- 分部汇总、财务传导和每股价值机械对账；
- 证据追溯测试覆盖每类正式判断；
- 版本不可变、修正和并发冲突测试；
- 缺失、冲突、陈旧、无权限、不可识别和模型不平衡的失败测试；
- 宁德时代与 Alphabet 跨行业契约测试；
- 桌面与移动端的核心阅读与可访问性测试。

## 19. 实施阶段

### 阶段 0：正式领域与数据契约

冻结术语、版本关系、类型、状态机、失败语义和组件接口。

### 阶段 1：不可变账本与历史基线

实现 Identity、HistoricalBasis、Reality / Belief / Decision / Calibration ledger、版本和 ChangeSet 的最小持久化闭环。

### 阶段 2：动力电池行业与宁德时代纵向切片

导入冻结真实资料，建立 IndustryState、EarningsEngine、3–5 个机制、预测、估值和第一版承保结论。

### 阶段 3：第二时间点与校准

导入后续冻结资料，生成 ChangeSet、跌后差分、更新动作并形成至少一个到期校准记录。

### 阶段 4：Alphabet 复用验证

使用相同内核组合不同机制包和估值适配器，验证公司 / 证券分离与跨行业可复用性。

### 阶段 5：持续刷新与更广覆盖

只有前四阶段通过后，才增加自动刷新、更多行业、账户协作或组合上下文。

## 20. 主要风险与控制

### 假严谨

风险：结构完整掩盖证据和机制薄弱。

控制：AnswerabilityGate、ResearchDebt、来源追溯和失败关闭优先于内容完整。

### 反向估值不可识别

风险：多组假设可支持同一价格。

控制：展示 ExpectationSurface 与 identifiability，不宣称唯一市场预期。

### 机制模板僵化

风险：跨公司复用退化为行业平均模板。

控制：生命周期、公司覆盖、历史校准和模板失配债务。

### 行业错误扩散

风险：行业判断错误自动污染多家公司。

控制：行业变化只生成影响列表和复核任务，人工确认后才更新公司模型。

### 用户负担

风险：三时钟、四账本、机制和版本导致流程过重。

控制：默认只显示判断、价格要求、最大反证、允许动作和下一验证；复杂证据按需展开。

### 数据许可与可得性

风险：一致预期和行业指标无法合法稳定获取。

控制：SourcePolicy、ProviderCapability、显式缺失和可回答性降级；第一阶段先用冻结可授权口径。

### 观点积累但能力不提升

风险：版本很多，却没有复盘预测偏差。

控制：CalibrationLedger 和到期验证强制进入正式闭环。

## 21. 最终成功定义

这套系统成功，不是因为能为任意公司生成完整内容，而是因为它能够稳定、诚实地回答：

1. 行业利润池和公司盈利引擎如何运作；
2. 当前价格要求哪些经营条件成立；
3. 我方与市场真正分歧在哪个可验证变量；
4. 新信息改变了事实、机制、预测、价值还是只有叙事；
5. 当前证据允许观察、等待、试探建仓、分步建仓还是不应介入；
6. 判断从上一个版本为什么改变；
7. 后来实际结果说明研究者在哪些地方持续犯错；
8. 同一内核能否跨行业工作而不复制结论或页面。
