# 结论优先事件研究工作台设计

## 目标

把事件研究的主入口从分散的“运行、计划、审核、结论”页面，收敛为一个能立即回答三个问题的工作台：

1. 当前能否下结论；
2. 哪些因素最可能解释市场反应；
3. 系统或研究员下一步应做什么。

用户调整因素后，系统保留已核验证据，重新归类并继续自动研究；不清空历史、不删除审计记录。

## 范围

本轮改造只处理事件研究工作台及其因素调整闭环。已有的来源准入、跨事件隔离、关键证据审核、结论证据门控保持不变并被复用。

不在本轮重做资料库、主题库、公司档案、通用图谱或后台运行管理页。

## 首屏状态

工作台根据生命周期输出一个主状态和唯一主动作。

| 状态 | 首屏判断 | 唯一主动作 |
| --- | --- | --- |
| 暂不能下结论 | 明示关键缺口与当前因素证据不足 | 编辑并继续自动研究 |
| 系统研究中 | 显示正在验证的因素和可靠证据进度 | 查看研究依据 |
| 有关键证据待审 | 明示待审数量和其影响因素 | 审核 N 条关键证据 |
| 可形成结论草案 | 显示草案已具备的证据边界 | 复核结论草案 |
| 结论已发布 | 显示本次判断、因素与变化 | 查看结论变化 |

每个状态均显示四个可靠进度项：已核验、待审核、无效来源、当前研究缺口。无效来源仅用于审计，不计入结论或待审动作。

## 因素工作区

因素卡按当前优先级展示名称、证据数、证据方向、置信状态和缺口。用户可：

- 新增因素；
- 修改因素名称或说明；
- 调整因素排序；
- 从当前研究范围移除因素。

保存时创建一个研究范围版本，包含变更说明和因素快照。移除因素不删除证据；它进入待归类或历史范围，不再支撑当前结论。改名和排序不会重新创建证据。

## 自动研究行为

保存因素后，系统执行以下顺序：

1. 将同事件、可采纳的已有证据重映射到新因素；
2. 标记不能合理映射的证据为待归类；
3. 根据每个因素的证据缺口创建下一轮自动研究范围；
4. 继续搜索和核验真实来源；
5. 仅在需要确认因素、判断关键证据或复核结论草案时请求人工。

页面使用自然语言说明当前研究重点，例如“正在核验资本开支指引是否足以解释盘后跌幅”，不显示 worker、JSON、任务标识或内部预算。

## 结论与证据边界

结论草案只使用当前事件、当前研究范围、可采纳且已发布的正式证据。草案必须显示：

- 当前判断和结论置信度；
- 排序后的关键因素；
- 每个因素的支持与反驳证据；
- 尚未解决的关键不确定性；
- 形成正式结论前仍需完成的唯一动作。

研究范围更新不会覆盖已经发布的历史结论；新信息应形成新版本或新的事件研究。

## 异常与无证据状态

当来源不足、自动研究失败或无法形成结论时，工作台不得生成伪结论。它应明确展示：

- 缺少什么证据；
- 已检查和排除过什么；
- 系统下一次将尝试什么；
- 用户可采取的动作：调整因素或补充来源。

## 验收与测试

至少覆盖：

1. 调整因素后，旧的已核验证据保留且被重新归类；
2. 移除因素不删除证据或审计记录；
3. 保存新研究范围后自动研究继续推进；
4. 没有足够证据时不生成结论草案；
5. 草案只引用当前事件的可采纳正式证据；
6. 五种首屏状态各自显示唯一、可理解的主动作；
7. 前端在窄屏下保持首屏判断、因素和主动作可读可用。
