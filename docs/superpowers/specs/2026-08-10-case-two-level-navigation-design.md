# Case 两层导航设计

## 目标

将单个 `ResearchCase` 的八个平铺页面入口收束为研究员可理解的五个工作阶段。导航应帮助用户完成当前研究动作，而不是展示系统的完整功能目录。

## 已确认的信息架构

Case 标题下只显示以下一级导航：

1. `研究结论`
2. `证据工作台`
3. `市场与表达`
4. `监测与运行`
5. `关系与图谱`

仅当用户进入包含多个专业工作面的一级阶段时，显示上下文二级导航：

| 一级阶段 | 二级入口 | 既有 URL |
| --- | --- | --- |
| 证据工作台 | 命题与证据 | `/events/:caseId/evidence` |
| 证据工作台 | 原文资料 | `/events/:caseId/documents` |
| 证据工作台 | 证据审核 | `/events/:caseId/review` |
| 关系与图谱 | Wiki 图谱 | `/events/:caseId/wiki` |
| 关系与图谱 | 关联研究 | `/events/:caseId/relations` |

`研究结论` 仍使用 `/events/:caseId`，`市场与表达` 使用 `/events/:caseId/market`，`监测与运行` 使用 `/events/:caseId/monitor`。

## 交互规则

- 现有 URL 和书签必须继续可访问，不能以重定向破坏具体页面。
- 直接访问某个二级 URL 时，一级导航自动选中其所属阶段，二级导航自动选中当前页面。
- 一级入口点击行为：`证据工作台` 默认进入“命题与证据”；`关系与图谱` 默认进入“Wiki 图谱”。
- 审核待办数量只在“证据工作台”上以文字徽标显示，不能另占一个一级标签或依赖红点。
- `history`、`scope`、`protocol`、`monitor/config`、股票与基金档案属于上下文深链接，不作为一级或二级常驻入口；它们必须保留返回所属阶段的明确路径。
- 桌面端一级导航保持可扫描，二级导航在对应内容标题前显示。窄屏不得要求横向滚动才能发现主要工作阶段；应使用紧凑的“更多研究内容”入口承载非当前的次级阶段，且保留可访问名称和键盘焦点。
- 内容页面不合并：原文、审核、图谱仍是独立工作面，收束的只是导航层级。

## 验收

1. 用户在五秒内能从一级导航辨认 Case 所处的研究阶段。
2. 访问全部既有 Case 深链接时，仍渲染原目标页面，且显示正确的一级和二级选中状态。
3. “证据审核”待办在证据工作台中可见，不再与市场、监测、关系等平级争夺注意力。
4. 桌面与 375px 宽度下均能使用键盘或点击到达全部一级、二级入口；主要阶段不靠横向滚动发现。
5. 路由、Case 结论、原文、审核、市场、监测和关系的既有 HTTP 与端到端测试保持通过，并新增导航层级回归测试。
