# 事件驱动研究与结论工作台设计

## 目标

把当前“运行、审核、资料、结论”分散的流程，改成一条研究员能理解并走完的主线：从一条新闻或异常事件出发，建立可证伪的问题，核验竞争性解释，发布可追溯的正式结论。

首要使用场景是“财报超预期但股价大跌”一类事件。产品必须帮助研究员回答：发生了什么、主要因素是什么、哪些证据支持或反驳这些因素、哪些关键解释仍证据不足。

## 核心对象

### 事件研究

`ResearchCase` 的创建入口改为事件研究，至少包含：

- 事件标题、发生时间、相关公司/股票、市场异常（价格或量能变化）；
- 新闻原文或来源链接；
- 一个明确、可被推翻的研究问题；
- 证据截止时间和适用范围。

创建采用“**粘贴信息 → AI 提取 → 人工校正 → 创建研究**”四步，而不是先要求研究员填写一张空表：

1. 研究员粘贴新闻正文、公告摘要、社媒线索或任何想研究的信息，并可补充来源 URL；
2. AI 提取事件时间、相关公司/代码、市场异常、一句话事件摘要，并显示为“AI 初步提取，需人工确认”；
3. AI 根据已确认信息生成一个可编辑的研究问题，以及 3–4 个候选竞争性因素；
4. 研究员可以直接修改或删除每一项，再选择候选因素后创建研究并开始收集证据。

AI 不得把提取结果或研究问题当作最终事实。无法从输入确定的字段必须留空并标记“需补充”，不能臆造公司、时间、价格变化或归因。

“主题”降级为归档标签。不能再以宽泛行业词（如“AI”“科技”）作为主研究对象；每个研究必须能回答一个具体事件问题。

每一条新闻、公告或市场异常都是一份独立的事件研究档案。研究总览的主要职责是列出这些档案，让研究员在不同事件之间快速切换并继续工作，而不是把多个新闻事件塞进同一个主题、命题或运行记录中。每一行至少显示事件标题、公司/代码、当前结论状态、系统正在核验的事项、最后更新和唯一待人工处理动作。

### 多轮研究与事件切换

事件研究不是一次性任务。某一轮无法形成结论或没有找到关键材料时，系统保留已审核证据、被否定的解释和已覆盖的来源，并以“继续研究中”进入下一轮自动搜索。下一轮必须从当前最大证据缺口出发，而不是从头重复；用户应能看到“上一轮确认了什么、这一轮正在补什么”，但默认只看到当前系统判断与进展。

切换研究意味着切换到另一条独立的新闻事件档案，不覆盖、不合并、更不改写已发布结论。用户在总览中选择另一事件后，应立即看到该事件自己的结论、因素、证据门槛和自动研究状态。跨事件复用来源时，只复用原文与其可追溯元数据，并重新判断其是否适用于新的事件问题。

### 竞争性关键因素

一个事件研究有 3–5 个候选因素，且这些因素是彼此竞争或互补的解释，例如：资本开支上调、自由现金流转负、业绩预期差、估值预期重估、整体风险偏好变化。

每个因素必须显示：

- 对当前结论的作用：主要支持、次要支持、反驳、待验证；
- 已审核的支持与反驳证据；
- 证据质量与适用边界；
- 最关键的缺口或替代解释。

没有来源、时间、范围、原文定位及人工审核状态的材料只能是候选材料，不能用于正式结论。

## 主流程

```text
新闻 / 价格异常
→ 创建事件研究与竞争性因素
→ 系统自动收集、扩展与交叉核验候选材料
→ 审核关键证据
→ 识别唯一关键缺口或冲突
→ 生成 AI 结论草案
→ 人工修改并确认正式结论
→ 新材料触发结论重审
```

### 自动研究与人工介入

研究创建成功后，系统立即自动启动研究，不要求研究员理解或手动推进“运行、提案、审核”等后台步骤。系统在允许的数据源与预算内循环执行：检索原始新闻、公告、财报、电话会、市场数据和可信分析材料；抽取正反证据；把材料映射至候选因素；根据证据缺口改写下一轮检索；交叉核验时间、范围和归因。

证据不足时，默认继续自动扩展搜索，而不是把模糊任务抛回给研究员。自动研究只在以下情况暂停并把问题交给人工：

- 已找到足以影响结论的关键证据，等待人工审核；
- 新一轮搜索没有实质新增信息、已覆盖允许来源，或达到研究预算；
- 输入本身存在重大歧义，不能安全判断研究对象、事件时间或研究范围；
- 涉及需要研究员选择的判断边界，例如是否纳入某类低可信来源或扩大比较区间。

人工始终可在不打断系统推进的情况下补充来源、指定要核验的因素、调整研究问题、停止或重新启动自动研究。系统仍是流程主导者：工作台只用自然语言显示一个当前状态，例如“正在核验资本开支是否足以解释盘后跌幅”或“尚缺电话会中管理层对自由现金流的解释”；后台任务、运行日志、原始 JSON、完整资料库和关系图均为“研究依据”的按需展开内容。

## 结论工作台

每个事件研究的默认页面固定为以下阅读和操作顺序：

1. **当前结论**：`尚不能下结论`、`AI 结论草案` 或 `已确认正式结论`。明确发生了什么、适用时间与范围，以及可能推翻结论的条件。
2. **关键因素**：至多五个，按对结论的影响排序。每项显示支持、反驳、缺口和当前作用。
3. **证据门槛**：已审核支持、已审核反驳、待审核候选、必须补齐的关键证据。不能用总证据数量替代证据含义。
4. **下一步，只做一件事**：由当前最大阻塞决定，例如审核两条关键提案、补齐一项反证，或生成结论草案。
5. **研究依据**：完整来源、运行记录、审核记录、图谱、历史版本。默认收起，不抢占主视图。

## 结论发布规则

AI 只能从已审核证据生成草案，草案必须包含：当前判断、主要/次要因素、竞争性解释、未解决风险、适用范围、证伪条件和可回溯证据。

研究员可以编辑草案，再确认发布。只有确认后的内容才能称为正式结论；存在缺口或冲突时，系统必须明确显示“尚不能下结论”，不得以运行成功或证据数量冒充结论。

## 页面与导航调整

- 首页改为事件研究列表与需要处理的“关键下一步”，不展示泛化运行仪表盘；
- 事件研究列表支持按公司/代码、结论状态、研究进展、待人工处理和归档标签筛选；点击任一事件直接进入该事件的结论工作台；
- `CaseWorkbench` 演变为默认的结论工作台；
- 自动运行、提案审核和评估审核从独立目的地变成上下文操作，仍保留深链接供追溯；
- 结论页只服务于已确认结论的阅读、回放与导出；
- 主题页只按事件研究归档和聚合，不生成主题级结论。

## 关键状态

| 状态 | 用户看到的内容 | 允许的下一步 |
| --- | --- | --- |
| 新事件 | 正在自动提取事件与建立候选因素 | 等待系统完成，或人工校正输入 |
| 自动研究中 | 当前检索方向、已覆盖来源、下一轮目标 | 继续自动研究，或人工补充限定条件 |
| 多轮继续研究 | 上一轮结论、保留证据、当前最大缺口与本轮检索方向 | 等待系统扩展搜索，或补充来源/限定条件 |
| 候选材料已到位 | 系统已筛出少量关键证据 | 审核关键证据 |
| 证据不足/冲突 | 系统正在扩展搜索，清晰列出缺口或竞争性解释 | 等待新结果，或人工指定范围/补充来源 |
| 可形成草案 | 门槛已满足、仍保留风险 | 生成结论草案 |
| 草案待确认 | AI 草案与证据基础 | 编辑、确认或退回补证 |
| 正式结论 | 确认人、时间、依据与证伪条件 | 监测新材料、发起重审 |

## 原型门槛与验证

实施前必须先完成并获得用户确认：

1. 事件研究创建入口原型；
2. 结论工作台高保真原型，覆盖结论、因素、证据门槛、下一步和依据展开；
3. 证据审核与结论确认原型；
4. 新事件、证据冲突、证据不足、草案待确认、正式结论五种状态。

实现后验证完整人工流程：从新闻建立事件研究，审核正反证据，发布结论，并能从任一结论或因素回到冻结原文与审核记录。
