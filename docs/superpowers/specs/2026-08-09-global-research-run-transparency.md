# 全局研究运行透明度

## 目标

任何系统正在执行的研究都必须对研究员可见、可解释、可回放。用户不应为了理解
“系统在做什么”离开当前的事件、结论、图谱、市场表达或审核工作。

## 常驻状态条

当至少一个 `ResearchRun` 处于 `queued`、`running` 或 `waiting_for_review` 时，应用外壳
展示状态条。它只显示：Case、阶段、确认过的因素范围、允许来源、已处理数量和下一人工动作。
状态条链接到当前 Case 的运行详情，不能把候选或运行计数包装成结论强度。

## 可展开运行详情

运行详情按照不可变事件序列展示：

1. 触发人或定时原因；
2. `CaseMonitorVersion`、频率、预算、因素和来源；
3. 检索、冻结、校验、候选、完成或失败的阶段事件；
4. 每个事件的时间、数量、受限/排除原因与可操作的下一步；
5. 运行结束后的三种结果：无关键变化、待审候选、可能需要重新复核。

没有权限的原文、供应商原始响应和其他租户资料只显示受限原因，不在详情中泄露。

## 配置与回放

用户可以调整频率、确认因素、允许来源、预算和下一验证事件，也可以暂停或立即执行。
即时与定时运行共用相同服务路径。每次保存都追加 `CaseMonitorVersion`，历史运行绑定原版本，
不得因后续配置改变而改变原有范围、输入或输出的解释。

## 验收

- 从任一 Case 子页能在五秒内看出活动运行的对象、阶段和下一步；
- 展开运行能解释处理了什么、为何排除了什么、是否产生待审候选；
- 无候选、失败和等待审核都使用不同且不误导的状态；
- 改动监控配置不会改写历史运行；
- 运行不会直接发布结论、市场表达或基金暴露。
