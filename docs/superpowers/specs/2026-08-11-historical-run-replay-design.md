# 工业富联历史运行回放设计

## 目标

让研究员能从同一案例的运行历史中明确选定一条运行、打开其冻结详情并在刷新或复制链接后回到同一条记录。首个验收对象是工业富联真实案例：既能查看旧的 `waiting_for_review` 运行，也能查看本次已完成人工审核的 `succeeded` 运行及其事件时间线。

这里的“回放”是读取已经冻结的运行范围、阶段、停止原因、人工审核结果和事件，不重新执行研究，也不改写历史记录。

## 范围与非范围

本次仅修改前端的监控页体验，复用现有 `GET /api/v1/research-cases/{case_id}/runs` 运行列表接口、监控接口和运行详情接口；不新增数据库表、后端写接口或运行状态机。

不在本次范围内：

- 新建研究运行、重跑、批量评分或历史记录编辑；
- 变更 AI 运行选择、审核判定或冻结范围的业务语义；
- 在列表中做运行比较、排序配置或无限加载；
- 修改原始证据、审核原因或历史事件。

## 界面结构

监控页采用常驻的内嵌“运行历史”列表（布局 A）。列表与现有运行详情工作区同时可见，而不是把历史入口藏在抽屉或二级页面中。

列表首期最多展示 20 条运行，每一行呈现：状态、当前/最终阶段、创建时间和停止原因。它是只读导航控件；点击一行只是选择该运行并打开现有详情抽屉/工作区，不会请求任何变更操作。

详情继续复用既有 `RunDrawer` 和运行详情数据：冻结范围、审核卡片、事件时间线和错误信息均保持其当前表达。这保证人工已完成审核的事件能在真实案例中被直接看见，而不是由列表重新拼装一份不可审计的摘要。

## URL 与选择状态

`?run=<runId>` 是当前选中运行的唯一来源。

| 场景 | 行为 |
| --- | --- |
| 带有有效 `run` 参数进入 | 选择该运行，加载并展示其详情。 |
| 不带 `run` 参数进入 | 选择监控接口返回的最新运行，并使用 replace 将其写入 URL。 |
| 点击历史列表某行 | 以该运行 ID 更新 URL（保留正常浏览器历史），然后加载相应详情。 |
| 刷新或复制带 `run` 的链接 | 仍选择同一运行，不依赖组件内存中的旧状态。 |
| 点击“返回最新运行” | 明确将 URL 改为最新运行的 ID，再加载该记录。 |

页面不得以“上一次选中的 React state”覆盖 URL，也不得在异步响应返回后把较晚返回的旧请求重新选中。所有详情、事件轮询和人工审核后的刷新都以当前 URL 中的运行 ID 为目标。

## 异常与恢复

若 `run` 参数不存在于该案例可访问的运行列表中，或该运行详情请求失败，页面展示清晰的“无法回放此运行”错误状态，并保留请求的运行 ID 供排查。此时不得静默切回最新运行，以免把不同冻结范围伪装成用户选择的历史记录。

错误状态提供“返回最新运行”这个显式恢复动作。只有研究员主动点击后，页面才更新 URL 并加载最新运行；若最新运行本身不存在，也显示无运行的空状态。

运行历史列表请求失败与当前运行详情请求失败分别展示。列表加载失败不应让已由 URL 成功加载的详情消失；详情失败也不应把列表中另一条运行当成替代内容。

## 数据和实现边界

前端通过既有 `researchClient.listResearchRuns(caseId)` 获取运行摘要，通过现有 monitor/detail/event 接口获得当前选中运行的详细只读视图。后端现有的案例归属和可见性校验仍是唯一授权边界，前端不以全局运行 ID 推断所有权。

在 `CasePages.tsx` 中，监控页将 URL 查询参数映射为选中 ID，并将历史列表、详情加载、事件加载和审核后刷新收束到同一选择流程。样式仅扩展研究操作系统的监控布局与历史列表响应式规则；窄屏下列表可在详情前纵向排列，但语义和 URL 规则不变。

## 验收标准

1. 工业富联真实案例可在历史列表中找到旧的 `967d6dc2-cd29-4205-aea3-f7dedc613e92`（`waiting_for_review`）和新的 `ec3f6d5c-7683-4495-ba20-5378ee0dc541`（`succeeded`）运行，并能来回切换。
2. 访问并刷新带 `?run=ec3f6d5c-7683-4495-ba20-5378ee0dc541` 的链接后，页面仍显示该次成功运行及“人工已完成临时 AI 评估审核”的事件，不跳回旧的待审核运行。
3. 无 `run` 参数时，页面选择最新运行并把其 ID 写入 URL；点击历史行后，URL 改为该行 ID，刷新后不丢失选择。
4. 无效、已不可访问或详情读取失败的运行 ID 显示明确错误，且不自动回退到任何其他运行；点击显式恢复按钮后才转向最新运行。
5. 前端单元测试覆盖有效 URL、无 URL 的默认选择、列表点击后的 URL 更新、刷新/重挂载后的选择保持，以及无效 ID/详情失败时不回退。
6. 真实人工浏览验收覆盖上述两条工业富联运行的切换与深链接刷新；全量前端类型检查、构建及相关测试保持通过。
