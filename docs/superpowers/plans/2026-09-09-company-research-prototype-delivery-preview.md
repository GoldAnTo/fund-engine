# 公司研究工作台：落地方案预览

日期：2026-09-09  
状态：待用户审阅；本轮只展示原型、整理方案，未开始实现。  
设计依据：[已确认的公司研究设计](/Users/xiongjiali/code/fund-engine/docs/superpowers/specs/2026-09-03-evidence-first-company-research-workbench-design.md)。

## 1. 准备做成什么

沿用已经设计好的七页公司研究工作台，让用户输入公司名称或证券代码，以及可选的关注问题，得到一份可以阅读、追溯依据、调整关键假设和保存版本的公司研究。

主路径是：

```text
选择公司 / 确认证券 / 可选关注问题
                  ↓
系统采集资料、冻结来源、分析公司
                  ↓
阅读初稿：怎么赚钱 → 经营驱动 → 情景预测 → 条件性价值判断
                  ↓
查看原文依据 / 处理关键输入 / 修改假设并重算
                  ↓
保存研究备忘录 → 导出 / 回放 / 比较版本
```

普通证据不逐条阻塞初稿。未通过适用复核的材料仍然是候选或未知，不能冒充已确认事实；关键输入不足时，只阻塞依赖它的预测、价值判断或保存动作，已具备依据的商业分析和缺口说明仍然可读。

用户面对的是公司和研究问题。原型的页面结构、阅读顺序、浅色纸面和深绿色导航作为实现基准。内部任务、产物哈希和调度信息放入必要的详情入口，不占据主要阅读区域。

## 3. 七页最终应该能做什么

| 页面 | 用户看到的内容 | 正式实现的验收点 |
| --- | --- | --- |
| 研究库 | 搜索公司、确认公司与证券、输入关注问题、最近研究和待处理项 | 搜索和创建接真实服务；刷新后可以继续同一份研究；重复提交不创建重复任务。 |
| 研究概览 | 研究边界、当前阶段、关键发现、可回答性、最大缺口、下一步 | 状态来自服务端；有部分结果就能阅读；失败时保留已有结果并解释可恢复原因。 |
| 商业模式 | 产品与客户、收入与定价、成本、资本占用、竞争位置、关键经营机制和反证 | 内容来自该公司该版本的研究；事实、指引、假设与未知明确区分；关键结论能打开对应证据。 |
| 预测与情景 | 历史基线、经营驱动、财务桥接、Base / Bull / Bear 及关键假设 | 每个数字能追溯父输入和计算；修改假设生成新候选并重算；三情景体现不同经营条件。 |
| 价值判断 | 价值区间、敏感性、当前价格隐含条件、市场数据时点、反证和阻塞原因 | 只使用满足条件的模型与市场快照；输入不足时展示具体缺口；接受缺口不能解锁无依据的估值。 |
| 证据中心 | 来源、原子陈述、支持与反驳关系、冲突、使用位置和复核状态 | 复核结果真实保存；被拒绝的材料不再进入后续模型；每个原文入口对应实际引用。 |
| 备忘录与版本 | 完整研究文章、关键输入处理记录、冻结版本、差异、回放和导出 | 保存后重新读取验证；回放不混入后来数据；版本比较展示真实变化；导出对应选中的冻结版本。 |

另外保留两个专用工作面：

1. **原文阅读器**：点击事实或数字，定位到对应冻结材料的页码、段落或表格单元格，同时看到上下文及它影响的模型和结论；按来源许可展示内容。
2. **关键输入确认**：集中处理会实质影响预测、价值判断或核心结论的输入。支持确认、修改假设、标记未知、接受缺口、补充授权资料；服务端记录每次决策及其对应版本。

“修改事实”必须转化为新的用户假设，保留原始来源事实。输入变化后，旧确认不能自动覆盖新版本。

## 4. 原型与真实产品之间需要补的工作

原型已经表达了目标体验，但不等于所有操作已落地。当前需特别区分：

| 部分 | 当前观察 | 本次落地责任 |
| --- | --- | --- |
| 公司与研究数据 | 原型来自 fixture；正式初始化目前仍偏 Alphabet 的固定适配路径 | 打通公司身份、研究运行和来源适配；首轮用 CATL 与 Alphabet 验证两种数据条件，不宣称已支持任意公司。 |
| 初稿生成 | 正式工作台仍存在所有证据处理完才进入模型构建的整体门槛 | 将可读初稿、证据准入、依赖关键输入的计算和保存条件分开处理。 |
| 搜索、关键输入操作 | 原型中部分控件没有持久化处理 | 接入真实读写接口、处理记录、错误状态和刷新恢复。 |
| 原文查看 | 原型主要展示按案例准备的示例文本 | 根据用户实际点击的引用读取精确原件位置与上下文。 |
| 保存、回放、比较 | 原型冻结主要存在会话存储中；部分回放和比较只显示提示 | 复用正式发布与回放能力，补齐公司研究版本差异的页面数据和真实操作。 |
| CATL 建模 | 仓库已有相关机制与财务计算模块，尚不能等同于完整公司研究生产链 | 将来源、证据、经营模型、情景、价值判断和发布串联起来，逐段验证。 |

两种案例代表两种输入条件，而不是按公司名称决定结果。正式系统不能写成“CATL 总能估值、Alphabet 永远不能估值”。

## 5. 准备怎么落地

以下是待审阅的交付顺序，尚未执行。每一步都有可供用户查看的页面与可验证操作。

### 第一步：打通研究入口和进度

- [ ] 接入真实公司/证券识别、研究问题和研究范围。
- [ ] 将现有公司研究能力映射为稳定的产品状态与七页数据接口。
- [ ] 落地研究库、概览和七页导航，具备加载、缺口、失败与恢复状态。

**交付效果：** 创建研究后能看见真实进度，刷新还能继续；暂未支持的公司明确说明支持边界，不套用别家公司的模板结果。

### 第二步：先产出可阅读的公司研究

- [ ] 连接资料准备、商业模式、经营驱动、财务桥接、情景和备忘录初稿。
- [ ] 按依赖关系区分可展示的内容、待确认内容与被阻塞的计算。
- [ ] 将原型中的结果页面接入真实研究数据，移除依赖具体公司名称的展示分支。

**交付效果：** 用户先读到有依据的分析；普通候选资料未全部处理时，已有结果仍可读；关键输入缺失时有具体缺口，不生成无依据的数值。

### 第三步：让关键结论能回到准确原文

- [ ] 将来源清单、证据关系和模型使用位置接入证据中心。
- [ ] 实现引用到精确冻结原文的阅读器。
- [ ] 支持受限展示、来源冲突、定位失效等明确状态。

**交付效果：** 从一个收入数字或经营判断点开，看到它实际引用的原文和上下文，并能追踪它影响哪些预测与结论。

### 第四步：关键输入确认与可追溯重算

- [ ] 根据模型依赖和影响规则生成关键输入队列。
- [ ] 持久化确认、假设修改、未知、缺口接受与补充资料记录。
- [ ] 新输入生成后继模型候选，更新预测、价值判断和保存条件。

**交付效果：** 用户修改一项假设后能看到计算结果与差异；原始事实和旧版本保留；接受缺口仍保留其对估值的限制。

### 第五步：保存、回放、比较与双案例验收

- [ ] 对接正式发布服务，保存备忘录及其确切输入和确认记录。
- [ ] 完成冻结版本的阅读、导出和真实差异比较。
- [ ] 用两个不同证据条件的公司案例走通真实接口、数据库、worker 和浏览器操作。

**交付效果：** 资料完整时可以验证预测和条件性价值判断；资料不足时保留商业分析、反证和缺口，在发布条件允许时保存诚实的“当前不可判断”备忘录。后来资料或假设变化形成新版本，旧版本可独立回放。

## 6. 实现边界与复用

以现有 React 公司研究入口、API 客户端和服务为基础，把七页原型落到正式前端。后端补充产品编排、页面数据、关键输入决策和精确阅读接口；来源治理、证据、模型、发布与回放继续调用现有能力。

主要对接位置：

- 前端入口：`frontend/src/app/CompanyResearchRoutes.tsx`
- 当前工作台：`frontend/src/features/investment-research/ResearchWorkbenchPage.tsx`
- API 客户端：`frontend/src/data/investmentResearchApi.ts`
- 初始化与资料准备：`backend/app/underwriting/services/company_research_initializer.py`、`company_research_preparation.py`
- 证据与工作台：`backend/app/underwriting/services/company_research_workbench.py`
- 模型与计算：`backend/app/underwriting/services/company_research_model_builder.py`、`company_research_engine.py`
- 发布与回放：`backend/app/underwriting/services/company_research_publication.py`

第一轮以这条公司研究路径可用为范围。FundClaw Gateway、事件更新、基金映射和更多行业适配不作为本轮完成的前提。后续财报或公告触发增量研究，放到主线稳定后的下一阶段。
